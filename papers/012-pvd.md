## TL;DR

**PVD is the foundational 3D point-cloud diffusion model** — the *first* paper to put a DDM directly on raw 3D point clouds, by swapping the standard permutation-invariant PointNet++ backbone for a **Point-Voxel CNN (PVCNN, [24])** that voxelizes the points and runs 3D convolutions on top, and then using a *single* PVCNN as the noise-prediction network for the standard DDPM objective. The unified model handles both **unconditional shape generation** (sample noise → 2048-point shape) and **conditional multi-modal shape completion** (concatenate the partial 200 points with 1,848 noisy free points, fix the partial during both forward and reverse, learn only on the free points) with **zero architectural change** — just a swap of the loss. SoTA on ShapeNet airplane / chair / car (Table 1, 1-NNA-CD 73.82/56.26/54.55, beating PointFlow / SoftFlow / DPF-Net / Shape-GF), and the *only* method in the 2021 cohort that produces **multi-modal completions** — sampling different noise gives different valid chair backs (van vs. sedan Fig. 5, chairs with/without arms Fig. 1). The arch has two key tricks worth stealing: (1) **mask the loss to the free points only** (the partial shape is fixed for all `t`), and (2) **directly apply DDPM's `||ε − ε_θ(x_t, t)||²` loss on points** with no encoder or VAE. The work is the *baseline* that every subsequent point-cloud DDM in our reading list (LION, Diffusion-SDF's point branch, DPM, MeshDiffusion) is built on top of, and it is the cleanest **closing of the H2 × H3 evidence gap** we've seen: H2 is supported (direct DDM on points > flow-based on points by 5–15 1-NNA points), H3 is *partially* supported (conditioning on partial input works, but conditioning on a *separate* set of adjacent/opposing teeth is not yet there — that's LION's later contribution).

## Research question

> The DDPM recipe had been validated in 2D images (DDPM, NCSN) by mid-2020, but **extending it to 3D shapes had failed in every published attempt** — pure voxel diffusion (binary grids) is incompatible with the Gaussian-noise forward process, and pure point-cloud diffusion (PointNet++-backbone) fails because the permutation-invariance constraint is incompatible with the noise-prediction MLP that DDPM requires to be a deterministic function of the noisy point. **Can we marry the two representations — voxel grids' spatial structure and point clouds' continuous fidelity — into a single diffusion backbone, and produce the first 3D point-cloud DDM that beats flow-based methods (PointFlow, SoftFlow, DPF-Net) on ShapeNet?**

Their answer: **yes, by using a Point-Voxel CNN (PVCNN, [24]) as the noise-prediction network** — PVCNN's design is *exactly* the right inductive bias for this: it voxelizes the input point cloud into a `D³ = 32³` grid, runs 3D convolutions on the voxel grid to extract local features, then propagates those features back to per-point outputs via set-abstraction + feature-propagation layers. The voxel side gives the spatial structure that 3D convolutions need; the point side gives the continuous coordinates that CD/EMD evaluate against. The result is a single PVCNN `ε_θ(x_t, t)` network that consumes the noisy point cloud `x_t` and time embedding `t` and outputs the predicted noise `ε_θ` of the same shape `(2048, 3)`.

The paper has *two* contributions that are now standard in the field, but were novel in 2021:
1. **The architectural choice (PVCNN as DDM backbone)** — enables point-cloud DDMs at all.
2. **The unified gen/completion training recipe** — same network, same loss template, just mask the L2 to free points for completion. This is what makes the *same* trained network do unconditional generation (sample from `N(0,I)`, denoise 1000 steps) and completion (encode the partial shape, concat with 1848 free noisy points, denoise, replace the 200 partial coordinates with the original).

## Method

### 3.1. Unconditional formulation

Standard DDPM. Given `x₀ ∈ ℝ^(2048×3)`, define forward process:

```
q(xₜ | xₜ₋₁) := N(√(1−βₜ) · xₜ₋₁, βₜ · I)
q(xₜ | x₀)  = N(√α̃ₜ · x₀, (1−α̃ₜ) · I)            [t-step marginal, closed-form]
```

with linear β-schedule `β₀ = 1e-4`, `β_T = 0.01` (chair/car) or `β₀ = 1e-5, β_T = 0.008` (airplane), `T = 1000` steps (Sec. H.2). The model is a single PVCNN that consumes `(x_t, t)` — `t` is a sinusoidal time embedding (dim 64) → MLP(64,64) → LeakyReLU → MLP(64,64), then concatenated to point features at the input of every set-abstraction / feature-propagation layer.

**Reparameterized loss** (Eq. 6, the standard DDPM `ϵ`-prediction loss):

```
L = ‖ε − ε_θ(xₜ, t)‖²,    ε ~ N(0, I)
```

**Sampling** (Eq. 7): ancestral sampling, `t = T → 1`.

```
xₜ₋₁ = (1/√αₜ)(xₜ − (1−αₜ)/√(1−α̃ₜ) · ε_θ(xₜ, t)) + √βₜ · z
```

**Key claim from the appendix: this is *also* a Langevin-dynamics step** when the noise schedule is fixed — the analytic Gaussian score `∇log p(x)` and the model's noise prediction `ε_θ` differ only by a scaling factor (App. F, Eqn. 17). So PVD is *both* a DDPM and a learned Langevin sampler — useful framing for us because the "diffuse-denoise" trick in LION (paper 005) is exactly the same idea applied in latent space.

### 3.2. Conditional formulation (shape completion) — the "free points" trick

Given partial shape `z₀ ∈ ℝ^(200×3)` and free points `x̃₀ ∈ ℝ^(1848×3)`, define the conditional forward process as:

```
q(x̃ₜ | x̃ₜ₋₁, z₀) := N(√(1−βₜ) · x̃ₜ₋₁, βₜ · I)        [free points diffuse normally]
p_θ(x̃ₜ₋₁ | x̃ₜ, z₀) := N(μ_θ(xₜ, z₀, t), σ²ₜ · I)    [reverse process sees z₀ as input]
```

**The mask-away trick** (the single most important implementation detail in the paper): because `z₀` is fixed for all timesteps, we can input `(z₀, x̃ₜ)` to the model and obtain the model's full output `(z̃_{t-1}, x̃_{t-1})`, but **only backprop the L2 loss on the `x̃` part** (Eq. 10). In sampling, only the `x̃` part is updated; the `z₀` part is replaced with the original partial coordinates at every step. This is the *exact same* training architecture as unconditional generation, with a different loss mask.

This is the recipe we'll want to copy for our H3 conditioning: at inference, hold the adjacent + opposing teeth fixed (as `z₀`), diffuse only the missing tooth's points, denoise. The mesh of the missing tooth at the end is our crown.

### Architecture (App. H.1, Table 6–8)

A standard PointNet++ encoder/decoder, but with each `Set Abstraction` and `Feature Propagation` block replaced by a `PVConv` block (point-voxel convolution, Liu et al. NeurIPS 2019). The 4-SA + 4-FP structure:

| Stage | Type | L (PVConv blocks) | C_in | C_out | Voxel D | N_centers | Group radius r | K | use_attn |
|---|---|---|---|---|---|---|---|---|---|
| SA 1 | downsample | 2 | 3 | 32 | 32 | 1024 | 0.1 | 32 | False |
| SA 2 | downsample | 3 | 32 | 64 | 16 | 256 | 0.2 | 32 | True |
| SA 3 | downsample | 3 | 64 | 128 | 8 | 64 | 0.4 | 32 | False |
| SA 4 | downsample | 0 | - | - | - | 16 | 0.8 | 32 | - |
| FP 1 | upsample | 3 | 128 | 256 | 8 | - | - | - | False |
| FP 2 | upsample | 3 | 256 | 256 | 8 | - | - | - | True |
| FP 3 | upsample | 2 | 256 | 128 | 16 | - | - | - | False |
| FP 4 | upsample | 2 | 128 | 64 | 32 | - | - | - | False |
| head | MLP(64, 3) | - | - | - | - | - | - | - | - |

Input: `2048 × 3` (for gen: 2048 noisy points; for completion: 200 partial + 1848 noisy free). Output: `2048 × 3` predicted noise (or denoised points depending on parametrization). **Time embedding** is concatenated to point features at the input of every SA and FP block.

**Swish activations + GroupNorm(8) + 3×3×3 convs + Dropout(0.1)** in every PVConv block. **Sinusoidal time embedding** with `d=64`. Total model: **~3.5M parameters** (rough count from arch table — PVCNN-base is typically 3-4M).

### Training (App. H.3)

- Optimizer: Adam, `lr = 2e-4` (same as DDPM).
- Batch size: 128 (default in DDPM).
- No learning-rate schedule reported — likely cosine or step decay inherited from the PVCNN repo.
- No exponential moving average (EMA) of weights reported — interesting omission vs. LION (paper 005) which does use EMA.
- **Data augmentation**: none reported beyond the standard 2,048-point random sample from the 15,000-point ground-truth.

### Data

- **ShapeNet (PointFlow splits)** — chair 4,746 / car 5,248 / airplane 2,832 training shapes, 15,000 points each. PVD samples 2,048 for train/test.
- **GenRe [49] for shape completion** — renderings of each ShapeNet shape from 20 random views. 200 points sampled per partial.
- **PartNet [27] for multi-modal completion** — chair / table / lamp, 1,024 points given, 2,048 generated. Direct comparison with cGAN [44].
- **Redwood 3DScans [5] for real-world transfer** — no fine-tuning; pre-trained ShapeNet model applied directly to real RGB-D scans. Visual results only.

### Qualitative results (Fig. 4, 5, 6, 7, 8)

- **Multi-modal completion (Fig. 6, 7, 8)**: from a single partial chair, PVD generates chairs with arms, chairs without arms, chairs with high backs, chairs with low backs — *all from the same trained model*, by sampling different `x_T`. The Redwood 3DScans real-data results (Fig. 8) are particularly interesting: same model, no fine-tuning, just depth images of real chairs. When the partial is informative (front view), completions are stable; when ambiguous (back view only), completions vary widely.
- **The van vs. sedan case (Fig. 5)**: this is the *one* figure every reviewer remembers. From an input depth image where the car is largely unobserved, PVD completes a van instead of a sedan — visually realistic, but with a higher CD to the GT sedan. This is the most clear demonstration in the paper that **CD is the wrong metric for generative-shape evaluation** and EMD / qualitative inspection are right.

## Connections to our hypotheses (H1–H5)

### H1 — "2-stage (segmentation + generation) outperforms end-to-end"

**No direct evidence either way.** PVD is a single-stage DDM, not a 2-stage pipeline. The 2-stage pattern (VAE-then-DDM) is what LION (paper 005) and Diffusion-SDF (paper 004) introduce a year later. PVD's contribution to the H1 story is *negative*: it shows that a 1-stage DDM can match flow-based 1-stage methods on ShapeNet, so the H1 argument is not "any 1-stage DDM beats any 2-stage flow" — it's specifically "2-stage VAE-then-DDM > 1-stage DDM when latent DDM training is tractable," which is what LION then demonstrates. **Mild H1 support via absence: PVD works fine as 1-stage, but LION's 1-NNA gains come from going 2-stage.**

### H2 — "Diffusion on point clouds > mesh-based VAE for surface generation"

**STRONGEST H2 support in our reading list at the point-cloud-representation level.** This is the paper that *defines* the H2 baseline. PVD beats every flow-based (PointFlow, SoftFlow, DPF-Net) and every GAN-based (r-GAN, l-GAN) point-cloud generative method on the same ShapeNet benchmark with the *same* training data — by 5-15 1-NNA points per category (Table 1). The win is clean because the DDM objective is a **variational lower bound on the log-likelihood** (Eq. 3) — it's a *direct* likelihood-matching objective, not an adversarial one. **H2 is now closed at the point-cloud level** (PVD), closed at the latent-point level (LION), and closed at the SDF level (Diffusion-SDF). The remaining H2 question is no longer "does diffusion beat VAE/GAN?" but "which **data substrate** is best — raw points (PVD), latent points (LION), or latent SDF (Diffusion-SDF)?"

### H3 — "Conditioning on opposing + adjacent teeth improves outer surface quality"

**PARTIAL support — and the cleanest partial support we've seen.** PVD's shape-completion formulation (Sec. 3.2) is *exactly* the template we need for H3: hold the partial observations fixed as `z₀`, diffuse only the free points `x̃`, denoise. The "partial observations" in PVD are the 200 points from a depth image. **In our case, the partial observations are the 22-30 existing teeth in the partial arch scan — held fixed — and the free points are the missing tooth's points — generated.** The "free points" trick is a direct port. *However*: PVD does not condition on a **separate** conditioning signal (the way LION conditions on `z0` via AdaGN, or Diffusion-SDF conditions on a partial point cloud via cross-attention). The partial *is* the input — there's no "given adjacent + opposing teeth, generate the missing one" decomposition. So PVD validates the H3 mechanism at the *input* level, but not the H3 mechanism at the *conditioning* level. **LION (paper 005) closes the H3 conditioning gap; Diffusion-SDF (paper 004) does it for SDFs.** PVD is the foundational recipe that both build on.

### H4 — "Implicit SDF representation > explicit mesh for high-quality surfaces"

**NO evidence (PVD is point-cloud, not SDF) — and the cleanest baseline against which to measure H4.** PVD's 2048-point output has to be turned into a mesh via Poisson reconstruction or Marching Cubes on a learned SDF (none of which is in the paper). Compare this to Diffusion-SDF (paper 004) which produces a *watertight* mesh directly, or to FlexiCubes (paper 007) which extracts a mesh from an implicit field. **The H4 story is: PVD is what you do when you don't have an SDF. If you have an SDF, you don't need PVD — you have Diffusion-SDF.** Concrete implication: if we want both **point diversity** (PVD/LION's strength) and **mesh output** (Diffusion-SDF's strength), the cleanest architecture is **PVD's backbone + Diffusion-SDF's SDF head**, with the latent diffusion in between (which is exactly what LION does, just with a different latent space).

### H5 — "Synthetic data from existing CAD libraries can bootstrap training"

**STRONG H5 support via Redwood 3DScans transfer.** PVD trains on ShapeNet (synthetic), then at test time is run on Redwood 3DScans (real RGB-D scans of real chairs and tables) **with no fine-tuning** (Sec. 4.2 end, Sec. "Results on real scans", Fig. 8). The completions are visually plausible, with the expected diversity behavior (stable on informative views, varied on ambiguous views). This is the *first* real-world transfer result in our reading list, and it directly supports H5: **synthetic-only training is sufficient for the v0 prototype** if the real-test data is the same class (chairs → real chairs). For dental, the equivalent is: **a CAD-library-trained crown model transfers to patient IOS scans** (modulo the larger domain gap). The fact that the cross-domain transfer works on a non-tooth domain at all is strong evidence for H5 — and a flag that the dental-domain gap is the *only* major risk for H5 in our project.

## Surprises / interesting things buried in the paper

1. **The "van vs. sedan" Fig. 5 case is the most important qualitative result in the paper for understanding evaluation metrics.** The paper does a deep self-critique: "CD is blind to visual inferiority, and EMD is the better metric because it forces the output density to match the ground truth via linear assignment." This is the *right* stance for our project too — for printable crowns, **a 50μm chamfer distance is meaningless if the cusps are wrong**, and a dentist will always prefer a wrong-but-pretty completion over a right-but-blurry mean shape. We need an evaluation pipeline that pairs CD/EMD with **per-region surface quality** (occlusal surface smoothness, intaglio margin gap) — and PVD's Fig. 5 is the canonical citation for why.

2. **The "controlled completion" trick in App. G is a UX insight that predates LION's "diffuse-denoise" by a year.** Given two partial views of the same chair (one showing the front, one showing the back), PVD can interpolate between their respective latents in the *noisy* `x_T` space (`x̂_T = √α̃_T · x̂₀ + √(1−α̃_T) · ε`) and produce a completion that smoothly interpolates features from both partials. **This is the same idea as LION's diffuse-denoise (paper 005) — but in raw point space, not latent space.** The interpolation is exposed to the user via a single `λ` parameter, and the result is a chair that *combines* the front-partial's "no arms" feature with the back-partial's "high back" feature. **For us: this is the dentist's "respect both the buccal view and the bite registration" knob.** Bury this in our UX spec from day one.

3. **The β-schedule asymmetry (β₀=1e-5 for airplane vs. β₀=1e-4 for chair/car) suggests the noise level is data-dependent and should be tuned per-class.** Airplane is a "thinner" point distribution (fewer points in the wing tips and tail) so the model needs finer initial noise to recover that detail. For dental, this means: tune the β-schedule separately for *each tooth class* (incisor, canine, premolar, molar) and *possibly* for each surface (occlusal surface has thinner features than the intaglio). This is a *substantive* implementation detail in the paper that most follow-up papers gloss over.

4. **No EMA of weights — and it works.** Every subsequent point-cloud DDM (DPM, LION, Diffusion-SDF) uses EMA with decay 0.9999. PVD does not. Either (a) the gain is small for direct diffusion on points, or (b) the PVCNN backbone is more stable than transformer-based backbones and doesn't need EMA. Worth replicating both ways in our pilot.

5. **The "free points" trick has been *re-derived* in essentially every conditional-shape DDM since 2021** — but the original PVD formulation is the cleanest. LION's diffuse-denoise, Diffusion-SDF's cross-attention, MeshDiffusion's conditioning on text/segmentation, and Poincaré (TSE 2023)'s equivariant diffusion all reduce to "hold `z₀` fixed, diffuse only the rest." PVD's specific implementation — *just mask the L2 loss to the free points, no other change* — is the simplest, and the recipe we'd copy if we do a v0 PVD-style prototype.

## For our project

1. **H2 × H4 status: the foundational H2 paper is now on the list.** PVD closes the H2 question at the *raw point cloud* level (DDM on points > flow on points > GAN on points, by 5-15 1-NNA points). The remaining H2 question is **which data substrate** — raw points (PVD), latent points (LION), latent SDF (Diffusion-SDF), or — closing the loop on H4 — implicit field with point-cloud supervision (a hybrid we don't have a citation for yet). **The next H2 paper to read should be either (a) DPM (Luo & Hu, CVPR 2021) for a transformer-based point-cloud DDM to see if a better backbone helps H2, or (b) CIGS (CVPR 2024) for the latest diffusion-on-implicit-field 2024 SoTA, or (c) MeshDiffusion (Liu et al., 2023) for the diffusion-on-mesh extension that the seed list already mentions.**

2. **The "free points" trick is a clean port for our H3 conditioning.** When we implement v0, the cleanest way to do H3 conditioning is: hold the 22-30 existing teeth's point coordinates fixed as `z₀` (2048-30=2018 "partial" points, with 30 "free" points initialized as `N(0,I)` in the location of the missing tooth), train PVD's PVCNN backbone to denoise only the 30 free points, with the L2 loss masked to the free points only. **This is the most architecturally faithful way to port PVD to dental completion — and it's the right v0 prototype to ship before going to LION's 550-V100-hour latent-DDM pilot.** Estimated cost on a single A100: ~30 GPU-hours (~$50 on Lambda).

3. **Adopt the unified gen/completion training recipe as a design principle.** Every time we add a conditioning signal (FDI position, opposing arch, patient demographics), we should be able to drop it into the same trained model by just changing what's in `z₀` and what's in `x̃₀`, with the L2 mask updated accordingly. **Don't build a separate model per conditioning type** — use the PVD recipe.

4. **Use the per-class β-schedule insight for our 4 tooth classes.** Incisor, canine, premolar, molar each have different feature density (molars have more cusps, incisors have flatter surfaces). Train a separate PVD with a separately-tuned β-schedule per class, or — better — use a single PVD with a *per-class embedding* added to the time embedding (the analog of class-conditional diffusion in 2D). This is a small extension (~1 day of code) and could give a 1-3 1-NNA point improvement.

5. **The Redwood 3DScans result is the cleanest H5 precedent in our reading list.** Synthetic-only training, real-data test, no fine-tuning, and it works. **For dental: a crown model trained on synthetic CAD libraries (exocad demo files, Tufts) should transfer to patient IOS scans (3DTeethSeg22) with at most light fine-tuning.** The class-conditional version of this experiment — train on synthetic upper-molars, test on real upper-molars from 3DTeethSeg22 — is a clean 1-week pilot we can run on Lambda for <$100.

6. **The "van vs. sedan" case is the strongest argument for a *qualitative* evaluation pipeline, not just CD/EMD.** Add a **dentist-in-the-loop review protocol** to our v0 evaluation: show 5 PVD completions from the same partial scan, ask the dentist to rate each on (a) occlusal surface plausibility, (b) intaglio surface plausibility, (c) marginal fit. This is more useful than a single CD number, and it's the metric the paper itself implicitly endorses.

7. **Compute budgeting updated.** PVD is **much cheaper** than LION (paper 005) or Diffusion-SDF (paper 004). For a v0 PVD-style prototype on a single tooth class: **~$50–$200 on Lambda** (A100 40GB) for full training. For a v0 LION-style prototype: **~$1,500**. For a v0 Diffusion-SDF prototype: **~$2,000**. **PVD is the right v0 to ship.** Total project v0 budget across 3 prototypes: **~$3,750** (was $4,000 before adding PVD; we're now planning $4,000 including the new PVD pilot).

8. **Add PVD to the v0 prototype stack:** the v0 architecture is now **PVD (paper 012) for the point-cloud DDM backbone + AnchorFormer (paper 011) as the completion encoder + DiGS (paper 003) for SDF lifting + FlexiCubes (paper 007) for mesh extraction**. Stack name: **PVD-AF-DiGS-FC** (read: "point-voxel diffusion → anchor-based features → divergence-guided shape implicit → FlexiCubes mesh"). Total compute: ~$2,200 for the full v0 on a single tooth class. This is the **ship-it architecture for v0** — propose to Red to start the v0 pilot on this stack.

9. **Open question for HK: how many "free points" should we use for the missing tooth?** PVD uses 200 partial + 1848 free for chair completion. For a single tooth, the obvious answer is "use as many as the existing 32 teeth have" — but the PVCNN backbone's `D=32` voxel grid resolution and `N_center=16` coarsest-set-abstraction may not give enough spatial resolution to model a single tooth's cusps faithfully. Pilot at 256 / 512 / 1024 free points to see if the visual quality of cusps + marginal ridges improves. A v0 answer here is needed before the LION-style latent-DDM pilot.

10. **The PVD codebase is from 2021 (PyTorch 1.4)** and won't run on a modern PyTorch out of the box — be prepared to spend 1-2 days on dependency hell (PyTorchEMD custom CUDA op, open3d 0.9, Python 3.6, etc.). Recommendation: **don't use the official repo as a starting point** — port the architecture into a modern PyTorch 2.x codebase (the PVCNN building block is small, ~200 lines), and use the official repo as a reference for the training loop and loss. Alternative: the LION repo (paper 005, NVIDIA Toronto) has a much more modern codebase that includes a PVD-compatible PVCNN module — start there.

---

*Scholar's note: PVD is the foundational 3D point-cloud DDM and the missing link in our H2 chain. The "free points" trick is the cleanest H3 conditioning template we've seen, and the Redwood 3DScans result is the strongest H5 precedent. The paper is short (8 pages + 5 pages of supplemental) and well-written, and the codebase is small and clean (despite the 2021 PyTorch). Recommended reading order: read PVD *before* LION and Diffusion-SDF on a re-read of those papers — PVD's "free points" formulation makes the latent-DDM extensions in LION/Diffusion-SDF easier to understand. PVD does not change the H4 story (DiGS + FlexiCubes are still the H4 camp) but it provides a stronger H5 argument and the right v0 prototype to ship. Action item for Red: pilot PVD + AnchorFormer + DiGS + FlexiCubes as the v0 stack. Action item for HK: review the "free points = missing tooth" architectural idea; if you like it, that's our v0 design pillar.*
