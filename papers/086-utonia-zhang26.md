## Research question + their answer

**Q:** The *single biggest open question* in 3D self-supervised learning after Concerto (paper 085) is *how to extend* the joint 2D-3D SSL paradigm *beyond* a single domain (indoor only for Sonata, indoor + video-lifted for Concerto) to *all five* point cloud domains (remote sensing, outdoor LiDAR, indoor RGB-D, object-centric CAD, video-lifted from RGB-only videos) in a way that *exceeds* the *sum of its parts* (i.e., the unified encoder should *outperform* per-domain specialists on every domain, *without* requiring per-domain pre-training). The three *specific* sub-questions are: **(a) How do we handle *inconsistent modality availability*** (indoor has color, outdoor LiDAR doesn't, object CAD has color from Cap3D, video-lifted has color from VGGT) without *either* (i) forcing all domains to a common modality interface (which *loses* the rich color information in indoor) *or* (ii) training per-modality encoders (which *loses* the unified-representation benefit)? **(b) How do we handle *granularity shifts*** (the same architectural operator can cover centimeters in object CAD but meters in outdoor LiDAR) without *either* (i) using per-dataset grid sizes (which *fragilely* couples features to domain-specific scale) *or* (ii) using a single global grid size (which *couples* features to a single scale and *loses* the per-domain optimization)? **(c) How do we handle *density non-uniformity*** (outdoor LiDAR is dense at close range and sparse at far range, indoor is dense, object CAD is uniform, video-lifted is reconstruction-noisy) without the *standard* sparse-convolution positional encoding that *couples* attention to the local neighborhood's discretization (which *breaks* under cross-domain density shifts)? Sonata (paper 084) and Concerto (paper 085) demonstrate that *pure-3D* and *joint 2D-3D* SSL can *exceed* DINOv2-lifted-to-3D by +9.4pp / +14.2pp on ScanNet linear probing (72.5% / 77.3% vs 63.1%), and that *naive* feature-concatenation (Sonata + DINOv2 = 76.44% linear probing) provides a *+3.9pp* gain over Sonata-alone. But the *central question* of Utonia is: **can a *single* self-supervised point encoder be trained on *all* point cloud domains simultaneously (without domain-specific modules) and *exceed* per-domain specialists on every domain, via three minimal domain-agnostic designs that fix the three sub-questions above?**

**A:** **Yes — and the *minimal* design is the *trilogy* of (a) Causal Modality Blinding, (b) Perceptual Granularity Rescale, and (c) RoPE on Granularity-Aligned Coordinates, applied to a *single* Point Transformer V3 encoder with teacher-student self-distillation following Sonata/Concerto (DINOv2-style restricted online clustering + KoLeo + Sinkhorn-Knopp centering), pre-trained in *two stages* (Stage 1 on 4 high-quality datasets for stable initialization, Stage 2 on the full 250k + 1M Cap3D mixture for 100 epochs).** The *three minimal designs* each fix one sub-question: **(a) Causal Modality Blinding** treats each modality group (color, normal) as *optional* except for coordinates, and applies random dropout at *two* levels (per-data: drop the entire modality group for a sample; per-point: drop the modality for individual points), the *direct* analogue of "training a person under deliberate vision deprivation" (paper's own analogy) so the encoder cannot *over-rely* on whichever modality is present, the *key* v0 v2 mechanism for cross-IOS-scanner deployment; **(b) Perceptual Granularity Rescale** draws a rescaling factor from a range based on the *original desired granularity* (analogous to "changing the observation distance so all objects project to the same angular resolution"), the *direct* fix for the granularity-shift problem (Table 2 shows per-dataset grid sizes cause ScanNet200 mIoU to drop from 34.4 (separate-domain) to 29.1 (joint with origin grids) to 33.5 (fixed grid + rescale) = *almost-recovered*; Waymo mIoU drops from 60.5 to 43.9 to 56.6 = *substantial recovery*); **(c) RoPE on Granularity-Aligned Coordinates** applies 1D RoPE to each of the three axis-subvectors `[u_x; u_y; u_z]` using the *rescaled* coordinates (with axis-wise jitter γ and isotropic scaling η as in DINOv3, the *canonical* augmentation for 3D RoPE), the *direct* fix for density non-uniformity (Table 7b shows RoPE adds +1.4pp on ScanNet200, +2.6pp on Waymo under multi-domain training, with the most pronounced gain on the outdoor Waymo benchmark where density varies *severely* within a single scan). The *key empirical insight* is that these three designs are *sufficient* to enable joint training: Table 7f shows that *scaling* the model from 38M/83k to 137M/83k to 137M/all-data yields *progressive* gains (e.g., Waymo 59.2 → 62.6 → 63.8 lin, PartNetE 44.6 → 45.6 → 39.8 lin, the *latter* is interesting because *more* data *hurts* linear probing on PartNetE — the *direct* evidence that part-aware features benefit from end-to-end adaptation, not from a fixed linear readout, the *same* finding as Sonata/Concerto's classification-vs-part-segmentation asymmetry). The *SOTA results* are *uniform* across all 5 indoor + 3 outdoor + 4 object benchmarks (Tables 3-5), and *extend* to non-perception tasks: 82.1% test success on tabletop manipulation (+1.4pp over Concerto, Table 9), 57.95% avg mIoU on PartObjaverse-Tiny open-world part seg (+2.4pp over Sonata, Table 8), and *uniform* SOTA on all 4 spatial-reasoning benchmarks (Table 10, ScanRefer 54.0% vs Concerto 52.6%, Multi3DRefer 54.1% vs Concerto 52.7%, Scan2Cap 83.9% vs Concerto 79.6%, ScanQA 30.5% vs Concerto 29.6%). The *cross-domain emergence* is the *qualitative* killer result (Fig. 2): a toy car from object CAD retrieves the *real* car in an outdoor LiDAR scene with high feature similarity, while Concerto fails to align — the *first* paper to *demonstrate* that a *unified* point encoder learns *cross-domain* object semantics, the *crucial* v0 v2 mechanism for "describe the prep tooth using features computed from a generic object encoder that has *also* seen cars, chairs, and street signs". The *gravity-alignment result* (Fig. 3) is the *second* qualitative killer: Sonata and Concerto features exhibit *strong z-correlated patterns* (height is used as a domain cue), while Utonia *weakens* this correlation — the *direct* evidence that the rotation-invariant object-data augmentation in Utonia's pre-training *erases* the gravity prior, the *crucial* v0 v2 mechanism for "the prep tooth can be in any orientation (the head can be tilted during scanning), and the encoder should be *invariant* to that orientation".

## Method

### The three failure symptoms (Section 2, the *pilot study*)

**Symptom 1: Sensitivity to granularity shifts.** In sparse point processing, the grid size defines the metric unit of local neighborhoods: the same architectural operator can cover centimeters in one domain but meters in another. Such granularity shifts change neighborhood statistics and local topology, altering how points are grouped and interact, and the learned features become coupled to the domain-specific scale. As shown in Table 2, *per-domain* optimal settings work well in *separate* training (ScanNet200 34.4 mIoU, Waymo 60.5, PartNetE 41.6), but *directly merging* domains makes joint training highly sensitive: using per-domain original grid sizes drops to 29.1/43.9/39.5 (a *5.3pp / 16.6pp / 2.1pp* drop), and *jittering* grid sizes only marginally helps (29.6/42.6/38.7 = a *4.8pp / 17.9pp / 2.9pp* drop from per-domain). The *fix* is to *unify* the grid size and *rescale* coordinates to a *consistent granularity* (Fixed grid size = 33.5/56.6/43.5 = a *0.9pp / 3.9pp / +1.9pp* drop from per-domain, *much better* recovery, the *direct* evidence that granularity alignment stabilizes joint training).

**Symptom 2: Bias toward gravity convention.** Many scene-level point clouds with a coarser granularity follow a *gravity-aligned* convention, making height a physical reference. Prior scene-centric training usually *avoids* strong x/y rotations, since many semantics depend on gravity (floor vs. ceiling, supporting surfaces). However, height can act as a *domain cue*, which hurts transfer to object-centric scans with a fine granularity. In Fig. 3, features from Sonata and Concerto exhibit *strong z-correlated patterns*, while Utonia *weakens* this correlation. The *fix* is to *treat gravity as a granularity-dependent prior*: retain upright structure for scene-scale scans, but *encourage* rotation invariance for fine-grained objects. The *implementation* is a *stronger* rotation augmentation for object-centric data: scenes get yaw augmentation in [-π, π] with mild roll/pitch in [-π/64, π/64], but objects get *full SO(3)* rotations sampled independently for all three axes in [-π, π] (Table 7a shows reducing object rotations to the mild scene-level setting significantly degrades performance on ScanObjectNN PB-T50-RS, which contains *strong* rotation/scale/shift perturbations).

**Symptom 3: Inconsistent modality availability.** Point clouds across domains expose different auxiliary channels beyond coordinates: indoor has color, outdoor LiDAR doesn't, object CAD has color from Cap3D, video-lifted has color from VGGT. In *naive* multi-domain pre-training, the encoder tends to *exploit* the richest available channels whenever they exist, since they provide strong cues that complement coordinates. However, the resulting *dependence* is unstable: when these modalities are missing, noisy, or defined differently, representations and performance can degrade. As shown in Table 6, Concerto performs well when both color and normals are available (e.g., ScanNet 80.7% f.t. with color, Waymo 71.2% with color), but degrades *substantially* when the modality is absent, *especially* colors (Concerto-lin ScanNet w/o color = 36.8% mIoU, a *catastrophic* 40.5pp drop; Concerto-lin NuScenes w/o color = 42.7% mIoU, a *catastrophic* 31.5pp drop). The *fix* is Causal Modality Blinding, applied at *data loading* time (Table 7d: dropping at loading yields 34.9/59.2/44.6 on ScanNet200/Waymo/PartNetE *with* color, *the best* of the three options; dropping on local views is also effective but slightly worse; dropping on masked views is *least* effective because masked views are already information-limited).

### The three enabling designs (Section 3)

**Design 1: Causal Modality Blinding (Section 3.1).** Define a *unified modality interface* as the default: concatenate coordinates + colors + normals, using *default zeros* for missing modalities. Then *intervene* on modality availability during pre-training explicitly: each modality group is *optional* except for coordinates, and apply *blinding* at two levels: **per-data blinding** randomly drops entire modality groups for a sample (e.g., "this entire scan has no color, so the color channel is set to zero for the whole sample"), and **per-point blinding** further masks modalities at individual points (e.g., "this specific point has no normal, so the normal channel is set to zero for this point"). The *ablation* (Table 7d) shows that *where* you drop matters: dropping at *data loading* is best (consistent modality-missing inputs across all objectives, the encoder cannot treat modality availability as a shortcut), dropping at *local views* is second-best (student learns to handle missing modalities while teacher provides complete guidance), dropping at *masked views* is worst (masked views are already information-limited, removing color/normal can over-corrupt the input). The *ablation result* is *striking*: in Table 6, Utonia with no color dropout during pre-training ("w/o drop") drops from 34.7 to 9.3 mIoU on ScanNet200 when color is *missing* at test time (a 25.4pp degradation), while Utonia with drop-at-loading pre-training drops from 34.9 to 31.7 (a 3.2pp degradation) — a *7×* improvement in robustness to missing color, the *direct* mechanism for v0 v2's cross-IOS-scanner deployment.

**Design 2: Perceptual Granularity Rescale (Section 3.2).** Point clouds are discrete samples of the same continuous 3D world, yet their spatial extent, sampling patterns, and coordinate conventions vary widely. The *fix* is to *rescale* coordinates so that each point cloud matches a shared perceptual granularity before positional encoding, mapping inputs from vastly different extents into a comparable coordinate space. The rescaling factor is *drawn from a range* based on the *original desired granularity*, exposing Utonia to different effective granularities during pre-training. The *insight* is that gravity alignment is a *granularity-dependent* prior: scenes with a coarser granularity should *retain* upright structure (height encodes stable physical relations), while objects with a fine granularity should appear in *arbitrary* orientations. The *implementation*: draw `r ~ U(log γ, -log γ)` for the rescaling factor, apply asymmetric scales/rotations/shifts in teacher and student views to enforce cross-view feature consistency, and at *inference*, the rescaling factor can be *adjusted* to match the desired granularity (the *one* place where the user can *tune* the granularity, the *direct* mechanism for v0 v2's "I have a CBCT-surface-extraction, what granularity do I use?" question).

**Design 3: RoPE on Granularity-Aligned Coordinates (Section 3.3).** Rescaling aligns the *basic spatial unit* across domains, but it does not specify how *relative geometry* should modulate token interactions. Sparse convolution encodes position through *discretization*, thus coupling interactions to discretization, local neighborhoods, and density non-uniformity. The *fix* is *continuous* positional encoding via 3D RoPE: split the feature vector evenly into three parts `[u_x; u_y; u_z]` and apply 1D RoPE to each subvector using the corresponding *rescaled + jittered* coordinate component. The *axis-wise jitter* γ is sampled from `U(-log γ, log γ)^3` (anisotropic per-axis), and the *isotropic scaling* η is sampled from `U(-log η, log η)` (uniform scale). The *ablation* (Table 7b) shows that RoPE *only* helps under multi-domain training: under single-domain training, RoPE *slightly hurts* ScanNet200 (34.0 vs 34.4 = -0.4pp) and PartNetE (42.4 vs 44.1 = -1.7pp) but *helps* Waymo (62.1 vs 60.5 = +1.6pp) because outdoor LiDAR exhibits *severe* density non-uniformity even within a single scan; under multi-domain training, RoPE *consistently helps* (ScanNet200 34.9 vs 33.5 = +1.4pp, Waymo 59.2 vs 56.6 = +2.6pp, PartNetE 44.6 vs 43.5 = +1.1pp), the *direct* evidence that RoPE's continuous relative-geometry cue *fixes* the cross-domain density-shift problem. The *RoPE base choice* ablation (Table 7c) shows stability across [1, 10, 100, 1000] — Utonia is *robust* to the RoPE base hyperparameter, the *practical* v0 v2 mechanism for "default RoPE base = 10, don't tune".

### The two-stage training schedule (Appendix A.1)

**Stage 1 (stable initialization):** pretrain the 38M model on a *curated* set of higher-quality datasets (ScanNet + Structured3D + Waymo + PartNet) to obtain a stable initialization. These datasets also correspond to the *ablation setting* in Table 7, so the ablation results are *exactly* the Stage-1 results. The 38M model uses channels [36, 72, 144, 252, 504] with depths [2, 2, 2, 6, 2], trained on a smaller compute budget.

**Stage 2 (full mixture):** continue pretraining for 100 epochs on the *full* 250k cross-domain mixture + 90k Cap3D objects per epoch, starting from the Stage-1 checkpoint. The 137M model uses channels [54, 108, 216, 432, 576] with depths [3, 3, 3, 12, 3]. Both stages adopt batch size 256 and are trained on 64 NVIDIA H20 GPUs. The *only* difference in training parameters between Utonia and Concerto/Sonata is that the upcast level for self-distillation is set to **0** (instead of 2 in Sonata) for faster training speed; empirically, this choice of upcast level has a *negligible* impact on downstream performance under sufficiently large-scale pre-training.

### The training data mixture (Table 12)

The total training data is **250,434 cross-domain point clouds + 1,006,782 Cap3D objects** (subsampled 90k per epoch to balance the mixture). The breakdown by domain:

- **Indoor (6 datasets, ~37k total):** ScanNet 1,613 + ScanNet++ 956 + S3DIS 272 + ARKitScenes 5,047 + HM3D 9,147 + Structured3D 20,005
- **Outdoor (4 datasets, ~120k total):** NuScenes 40,157 + Waymo 29,667 + SemanticKITTI 43,552 + HK Remote 6,136 (the *only* HK dataset, a remote-sensing dataset from HK)
- **Object (3 datasets, ~48k total):** PartNet 32,537 + ScanObjectNN 2,903 + GraspNet 12,160
- **Video-lifted (1 dataset, ~46k total):** RE10K 46,282 (reconstructed using VGGT or provided camera parameters)
- **CAD (1 dataset, 1M total):** Cap3D 1,006,782 (subsampled 90k per epoch)

For datasets without paired images (PartNet, ScanObjectNN, HK Remote), the cross-modal joint prediction from Concerto is *not* applied (only the intra-modal self-distillation). For outdoor datasets, image colors are projected onto points using the provided calibration, with default black for unobserved points. Surface normals are estimated with Open3D, with directions from points to the LiDAR center. For video-based data, point clouds are reconstructed using provided camera parameters when available (GraspNet) or feed-forward reconstruction (VGGT, for RE10K).

### Ablations (Table 7)

- **(a) Stronger scale augmentation for objects:** "less scale aug." (object data uses ±10% like scene data) drops ScanObjectNN-H from 66.9 to 64.5 (-2.4pp) and PartNetE from 44.6 to 43.0 (-1.6pp); "less rot. aug." (object data uses mild scene-level rotations) drops ScanObjectNN-H from 66.9 to 63.0 (-3.9pp) and PartNetE from 44.6 to 47.5 (+2.9pp, because PartNetE is gravity-aligned). The *trade-off*: stronger aug helps robustness to OOD perturbations but can hurt gravity-aligned eval, the *direct* mechanism for v0 v2's "use stronger aug for intra-oral scans (which can be in any orientation) and weaker aug for CBCT (which is gravity-aligned)".
- **(b) RoPE effects across domains:** Single-data baseline ScanNet200 34.4 / Waymo 60.5 / PartNetE 44.1; single-data + RoPE 34.0 / 62.1 / 42.4 (Waymo +1.6pp is the *only* gain); multi-data baseline 33.5 / 56.6 / 43.5; multi-data + RoPE 34.9 / 59.2 / 44.6 (ScanNet200 +1.4pp, Waymo +2.6pp, PartNetE +1.1pp). The *direct* evidence that RoPE's continuous relative-geometry cue is the *right* fix for cross-domain density shifts.
- **(c) RoPE base choice:** stable across [1, 10, 100, 1000] (ScanNet200 34.0-34.9, Waymo 59.2-60.6, PartNetE 43.7-45.0). Default B=10. The *practical* v0 v2 mechanism: "don't tune RoPE base, default to 10".
- **(d) Modality blinding:** w/o drop on ScanNet200 with color = 34.7, w/o drop w/o color = 9.3 (catastrophic 25.4pp drop); drop at loading with color = 34.9, w/o color = 31.7 (only 3.2pp drop, *much* better); drop at masked views is *worst* (with color 34.1, w/o color 10.1 — back to catastrophic 24.0pp drop). The *direct* evidence that *where* you drop matters, and *data loading* is the *right* place.
- **(e) Augmentations:** frame aug and scale aug help (w/o frame aug ScanNet200 -0.8pp, w/o scale aug PartNetE -2.0pp); RoPE aug is marginal (w/o RoPE aug +0.1pp ScanNet200, -0.9pp Waymo, -0.5pp PartNetE).
- **(f) Scale up:** 38M/83k → 137M/83k → 137M/all-data yields progressive gains (e.g., Waymo 59.2 → 62.6 → 63.8 lin, PartNetE 44.6 → 45.6 → 39.8 lin, the *latter* is interesting because *more* data *hurts* linear probing on PartNetE — the *direct* evidence that part-aware features benefit from end-to-end adaptation, not from a fixed linear readout, the *same* finding as Sonata/Concerto's classification-vs-part-segmentation asymmetry).

## Connections to H1-H5

**H1 (2-stage segmentation + generation > end-to-end):** **MILD SUPPORT.** Utonia is itself a 2-stage system (pre-training + downstream probe), and the *uniform* SOTA across 4 indoor + 3 outdoor + 4 object benchmarks with *only* a *linear probe* on top of a *frozen* pre-trained encoder is the *strongest* H1 evidence in the 86-paper reading list: a single 2-stage pipeline matches or exceeds *single-stage + supervised-auxiliary* baselines on every domain. The *practical* v0 v1 mechanism: pre-train Utonia-style encoder once, *all 5 sub-tasks* (segmentation, margin, intaglio, outer, mesh) become 2-stage problems with a small linear-probe head on top of frozen features, the *exact* DINOv2-paradigm that makes foundation models *practical*.

**H2 (diffusion on point clouds > mesh-based VAE):** **NEUTRAL.** Utonia does *not* address generation directly — it is a *pre-training* method, not a generation method. The *indirect* connection: Utonia's pre-trained features are the *latent space* for downstream H2 generation models (LION, Diffusion-SDF, PVD), and the *cross-domain* features are *richer* than Sonata's single-domain features, so H2 generation models that use Utonia features as the *conditioning latent* should be *better* than the same models with Sonata features. The *concrete* v0 v1 mechanism: use the released Utonia 38M checkpoint as the *frozen encoder* for PVD's free-points conditioning (paper 012), replacing the per-task trained encoder with a *cross-domain* encoder that has *also* seen CAD objects and video-lifted scans.

**H3 (conditioning on opposing + adjacent teeth improves outer surface):** **STRONG SUPPORT — the H3 mechanism is the *granularity rescale + cross-domain transfer* story.** Utonia's *entire* contribution is the *mechanism* that makes H3 work: a single encoder that *transfers* across domains (scanner types, granularities, modalities) is the *direct* solution to "conditioning on a *different* scanner's representation of the opposing/adjacent teeth". The *concrete* v0 v1 mechanism: at inference time, the prep tooth scan from scanner A and the adjacent/opposing teeth scans from scanner B (a *different* scanner in a different clinic) are *both* encoded by the *same* Utonia encoder (because the encoder is *cross-scanner-invariant* via Causal Modality Blinding) and the *features* are used as the H3 conditioning. The *crucial* v0 v2 mechanism: pre-train Utonia on a *dental-specific* mixture (50k clinical scans + 50k CBCT surfaces + 50k intra-oral photos + 1M Cap3D-style dental CAD models) to learn a *dental-specific* cross-domain representation, the *first* dental-specific 3D foundation model.

**H4 (implicit SDF > explicit mesh):** **NEUTRAL.** Utonia is purely *point-based* (no SDF, no mesh). The *indirect* connection: Utonia's pre-trained features are the *encoder* for downstream H4 implicit-SDF models (DiGS, Diffusion-SDF), and the *cross-domain* features should produce *better* DiGS fields than Sonata's single-domain features. The *concrete* v0 v1 mechanism: use Utonia features as the *conditioning input* to DiGS (paper 003) for the outer surface generation, replacing the per-task trained DiGS encoder with a *cross-domain* encoder that has *also* seen CAD objects. The *mesh extraction* (FlexiCubes, paper 007) is *unchanged*.

**H5 (synthetic data from existing CAD libraries can bootstrap training):** **STRONGEST SUPPORT — the H5 mechanism is the *Cap3D mixture* story.** Utonia's training data includes **1,006,782 Cap3D objects** (subsampled 90k per epoch), the *largest* synthetic data source in the 86-paper reading list. The *ablation* (Table 7f) shows that *adding* the 1M Cap3D data to the 83k cross-domain mixture yields *progressive* gains on indoor (ScanNet200 36.0 → 36.4 lin) and outdoor (Waymo 62.6 → 63.8 lin, the *biggest* gain), the *direct* evidence that *synthetic* Cap3D data is a *legitimate* pre-training source that *complements* real cross-domain data. The *crucial* v0 v1 mechanism: pre-train a *dental-specific* Utonia on the 1M Cap3D dental CAD models (when they are available, the *one* gap) + 50k clinical scans + 50k CBCT surfaces, the *first* dental-specific 3D foundation model that uses *synthetic* CAD as the *primary* pre-training source. The *practical* v0 v1 mechanism for *cross-clinic* deployment: pre-train on *one* clinic's 50k clinical scans (synthetic + real) + the released Utonia 38M weights as *initialization*, *exactly* the DINOv2 + Cap3D paradigm that makes image foundation models *practical*.

## Surprises / interesting things buried in the paper

**Surprise 1: RoPE *only* helps under multi-domain training.** Table 7b shows that RoPE *slightly hurts* ScanNet200 (-0.4pp) and PartNetE (-1.7pp) under single-domain training, but *helps* all three domains under multi-domain training. The *interpretation*: RoPE's continuous relative-geometry cue is *not* needed when the encoder is *specialized* to a single domain (the domain-specific sparse-conv positional encoding is sufficient), but is *crucial* when the encoder must *transfer* across domains (the continuous RoPE cue is *invariant* to the domain's specific discretization choices). The *practical* v0 v2 mechanism: RoPE is the *right* design for *multi-domain* pre-training, not for *single-domain* pre-training. The 1.4-2.6pp gain is the *minimum* that RoPE provides; the *real* value is *robustness* to the cross-domain density shifts that v0 will *encounter* in clinical deployment.

**Surprise 2: The "gravity alignment" prior is *erasable* via object-data augmentation.** Fig. 3 shows that Sonata/Concerto features exhibit *strong z-correlated patterns* (height is used as a domain cue), while Utonia features are *gravity-irrelevant* for object-centric data. The *interpretation*: by including object data with *full SO(3)* rotations, Utonia *erases* the gravity prior for *object*-level features while *retaining* it for *scene*-level features (the *granularity-dependent* gravity design). The *practical* v0 v2 mechanism: the prep tooth is in *any* orientation (the head can be tilted during scanning), and the encoder should be *invariant* to that orientation, the *crucial* property for clinical deployment.

**Surprise 3: The "where to drop modality" ablation has a *7×* robustness difference.** Table 7d shows that dropping at *data loading* yields 31.7 mIoU on ScanNet200 w/o color (only 3.2pp drop from 34.9 with color), while dropping at *masked views* yields 10.1 mIoU (24.0pp drop, *back to catastrophic*). The *interpretation*: the *consistency* of modality-missing inputs across all objectives (when dropping at loading) is *crucial*; if you drop *only* on masked views, the encoder still learns to *expect* complete modalities on local/global views, and missing modalities at test time cause a *catastrophic* degradation. The *practical* v0 v2 mechanism: when implementing Causal Modality Blinding for v0 v1, drop at *data loading* (consistent across all views), not at *view-specific* time.

**Surprise 4: The "scale up" ablation shows *more* data *hurts* PartNetE linear probing.** Table 7f shows that scaling from 137M/83k to 137M/all-data *improves* Waymo linear probing (+1.2pp) but *hurts* PartNetE linear probing (-5.8pp). The *interpretation*: more data *strengthens* object-level semantics (favoring classification) but *weakens* part-aware cues (because part cues are *fine-grained* and benefit from *task-specific* adaptation, not from a fixed linear readout). The *practical* v0 v2 mechanism: use a *query-based decoder* for part segmentation (not a linear probe), the *exact* direction Utonia's "Future Work" section recommends. For v0 v1, use Utonia features with a *small* task-specific decoder head (1-2 trans blocks) for part segmentation, not a linear probe.

**Surprise 5: The "upcast level 0" choice is *sufficient* under large-scale pre-training.** Sonata/Concerto use upcast level 2 (the level where 3D-specific geometric information is preserved), but Utonia uses upcast level 0 (the *highest-resolution* level) for *faster* training. The *interpretation*: the geometric-shortcut problem (which motivated Sonata's upcast-level-2 design) is *less severe* under large-scale multi-domain pre-training (because the *data scale* provides sufficient signal to learn 3D-specific features), so upcast level 0 is *sufficient*. The *practical* v0 v2 mechanism: when pre-training on *1M+* dental samples, use upcast level 0 (faster training), not upcast level 2 (Sona's design).

**Surprise 6: The HK Remote dataset (6,136 samples) is *included* in the training mixture.** Utonia includes a 6,136-sample "HK Remote" dataset (likely a remote-sensing dataset from Hong Kong, *not* explicitly described in the paper), the *only* HK-specific data in the 86-paper reading list. The *practical* v0 v2 mechanism: when v0 v2 pre-trains on dental data, include *both* clinical-internal data (the *primary* source) and *public* dental data (3DTeethSeg, ToothFairy, the *secondary* source), the *exact* "HK Remote" inclusion pattern.

**Surprise 7: The channel constraint (divisible by 6) is a *minor* practical gotcha.** Because RoPE is applied in 3D by splitting the channel dim into 3, the channel count must be **divisible by 6** (3 axes × 2 for real/imaginary RoPE rotation pairs). The 137M model uses channels [54, 108, 216, 432, 576] and the 38M ablation uses [36, 72, 144, 252, 504] — both are *divisible by 6*, but the *exact* channel choices are *constrained* by the RoPE design. The *practical* v0 v1 mechanism: when designing custom dental transformers, ensure channel counts are *divisible by 6*, otherwise RoPE will fail to apply.

**Surprise 8: The "modality blinding at data loading" insight is the *v0* mechanism for v0's *cross-clinic* deployment.** The single *biggest* practical contribution of Utonia for v0 is the *modality blindness* result: a pre-trained encoder that *robustly* handles missing color (or missing normal) is the *direct* solution to v0's *cross-clinic* deployment problem (some clinics have color IOS, some have only-texture IOS, some have only-CBCT, etc.). The 40.2pp gap between Utonia (77.0%) and Concerto (36.8%) on ScanNet w/o color is the *single largest* robustness gain in the 86-paper reading list, the *direct* mechanism for v0 v1 to *ship* to clinics with different scanner types *without* per-scanner fine-tuning.

The 38M model is *fast enough* for v0 v1 inference (chair-side dental-AI requires <5s per crown, the 38M PTv3 with 1cm grid size can do 5-10s per scan on a single A100). **Action: clone the Concerto repo, download the 38M checkpoint, fine-tune end-to-end on 3DTeethSeg22 + 5 clinical scans, measure the linear-probe F1 on 100 held-out scans, target ≥ 0.95 F1 (matching Cao 2025, paper 026).** Expected timeline: 1 week for plumbing + fine-tuning + evaluation, $200 Lambda cost.

**2. APPLY Causal Modality Blinding to v0 training.** Many dental IOS scans are *color-less* (model scans from CBCT) or *normal-less* (raw IOS without preprocessing). Utonia-style random modality dropout during v0 v1 fine-tuning will *prevent* the encoder from over-relying on whichever modality is present. **Action: add a `RandomModalityDropout(p=0.3)` transform to the v0 training pipeline (drop color with 30% probability, drop normal with 30% probability), train for 100 epochs, measure the test-time degradation when color/normal is missing, target <5pp degradation.** Expected timeline: 1 day for the transform, 3 days for the training, $100 Lambda cost.

**3. APPLY Perceptual Granularity Rescale to v0.** Intra-oral scans (mm-scale, 1024 points per tooth) vs model scans (cm-scale, 16384 points per tooth) vs CBCT-surface-extraction (sub-mm-scale, 4096 points per tooth) need granularity alignment. Utonia's 0.02m grid size is a reasonable default but should be re-tuned for dental scales. **Action: implement a `PerceptualGranularityRescale(target_grid_size=0.001)` (1mm) for v0, downsample intra-oral scans to ~1024 points per tooth via FPS, retrain, measure the linear-probe F1.** Expected timeline: 1 day for the transform, 3 days for the training, $100 Lambda cost.

**4. USE 3D RoPE for any custom dental transformer.** The field has *converged* on 3D RoPE since 2024, replacing PTv2's relative positional encoding. **Action: when designing v0 v1's custom dental transformer (if any), use 3D RoPE with base=10 and the channel-divisibility-by-6 constraint.** The 3D RoPE is the *right* design for *any* point-based transformer.

**5. For clinical deployment, use the 38M model (not 137M).** The 38M model is competitive with 137M when only 83k data is used (Table 7f), the *exact* v0 data budget. The 137M model is *only* worth the extra compute when v0 has *all* 250k cross-domain data, the v0 v2 milestone. **Action: for v0 v1, use the 38M model; for v0 v2, scale to 137M.**

**6. SKIP the v0 v2 multi-modal pre-training stage for now.** Utonia + Utonia-style pre-training is the v0 v2 endgame, but it requires 64 H20 GPUs and 1M+ data, *not feasible* for v0 v1. The 38M model *linear-probed* on dental data is the *practical* v0 v1 path, and the v0 v2 dental-specific pre-training (50k clinical + 50k CBCT + 50k IOS photos + 1M Cap3D dental = 1.15M) is the v0 v2 milestone, $3000-5000 Lambda cost.

**7. CONSIDER pre-training v0 v2 on the released Utonia 38M weights as initialization.** Instead of pre-training from scratch (which requires 64 H20 GPUs), initialize v0 v2's dental-specific encoder with the released Utonia 38M weights and *continue* pre-training on dental data. This is the *practical* v0 v2 path, ~10× cheaper than from-scratch pre-training, $300-500 Lambda cost. **Action: clone the Concerto repo, download the 38M checkpoint, add a 50k clinical + 50k CBCT + 50k IOS photos + 1M Cap3D dental = 1.15M dental-specific pre-training mixture, continue pre-training for 50 epochs, measure the linear-probe F1 on 100 held-out clinical scans.** Expected timeline: 1 week for plumbing + pre-training + evaluation, $500 Lambda cost. **This is the *killer* v0 v2 experiment.**
