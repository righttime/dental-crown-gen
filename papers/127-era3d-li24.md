# Paper 127 — Era3D: High-Resolution Multiview Diffusion using Efficient Row-wise Attention

**TL;DR.** The first single-view 3D-reconstruction pipeline that *solves the camera-intrinsic-mismatch problem* (Wonder3D/SyncDreamer assume orthogonal cameras → fail on real perspective photos) and *scales multi-view diffusion to 512×512* via a novel **row-wise multiview attention** layer that exploits the epipolar-row-alignment of canonical-camera setups to reduce attention complexity from O(N²S⁴) → O(N²S³) — 12× speedup with xFormers, **30× memory reduction / 100× runtime reduction at 512²** without xFormers. Built on SD2.1-unclip + 6 orthogonal views + 16 H800s for 30h. SOTA on GSO + OmniObject3D + in-the-wild, +12% PSNR over Wonder3D, +3% Volume IoU, -12% CD. AGPL-3.0 (not commercial).

## Research question + their answer

**Q.** Can we generate high-resolution (512²) consistent multi-view images from a single input image with *arbitrary* camera intrinsics (focal length, elevation), without the perspective-distortion artifacts that plague Wonder3D/SyncDreamer/Zero123++ when the input deviates from their assumed orthogonal camera?

**A.** Yes — via three contributions:
1. **Camera canonicalization**: input can be perspective at any focal length/elevation; outputs are always 6 orthogonal views at elevation=0° (azimuth offsets {β, β±45°, β±90°, β+180°})
2. **EFReg (Elevation+Focal length Regression) module** that runs in the UNet at every denoising step — AvgPool of the middle-block feature map H → 3-layer MLP → regresses (α̃, f̃), supervised by MSE loss against ground-truth, the predicted values are *also* fed back as denoising conditioning (the *condition scheme* part of "Regression and Condition Scheme")
3. **Row-wise Multiview Attention (RMA)** — when output cameras are *all orthogonal at elevation=0°*, epipolar lines across views are *horizontally aligned*, so the attention pattern collapses to **row-wise cross-view attention** (each token at row r attends to all tokens at row r in *every other* view, *not* the full N×S²×S² dense attention). Complexity drops from O(N²S⁴) to O(N²S³), and at 512² that's a 30× memory + 100× runtime win without xFormers (and 12× with xFormers).

## Method (architecture + training + data)

### Architecture

Pipeline (Fig. 4 of paper):
1. **Input image** (RGB, any focal length, any elevation) + **SD2.1-unclip** (image-conditioned UNet) as backbone
2. **EFReg module** in middle-block: global AvgPool(H) → MLP R₁, R₂ → predict (α̃, f̃); these are *added to* the diffusion timestep embedding in every residual block
3. **6-view diffusion** in canonical camera setting (6 orthogonal views at elevation=0°, azimuths = input-azimuth β + {0, ±45°, ±90°, 180°})
4. **Each view produces 2 modalities**: RGB image + normal map (joint generation, like Wonder3D)
5. **Multi-view consistency via RMA**: for each row index r ∈ [0, S), token features at row r across all 6 views attend to *all* token features at row r in the other 5 views (i.e., the attention is "row-block diagonal across views")
6. **Mesh extraction via instant-nsr-pl** (Instant-NSR, an Instant-NGP + SDF variant) on the 6 RGB + 6 normal views

### Training data

- **Objaverse** (Deitke 2023) subset — render 16 ground-truth images per object with **orthogonal cameras** at evenly distributed azimuths [0, 360°] and **fixed elevation 0°**
- For each of the 16 azimuths, render **3 more perspective images** (random elevation in [-20°, 40°], random focal length in {35, 50, 85, 105, 135} mm) + **1 more orthogonal image** (for ortho-only variant)
- All renderings at **512×512**
- This *mixed-intrinsic training* is the key innovation — it teaches the UNet to "rectify" the input perspective to output orthogonal canonical views

### Training

- **Hardware:** 16 × H800 GPUs (each 80GB) — that's 1280GB VRAM total
- **Batch size:** 128 global
- **Steps:** 40,000
- **Learning rate:** 1e-4 → 5e-5 after 5,000 steps
- **Time:** ~30 hours (~1.25 days)
- **CFG dropout:** 0.05 (randomly omit the clip condition during training)
- **Inference:** DDIM 40 steps, CFG scale 3.0
- **Total inference time:** ~4 minutes (13s for multi-view diffusion + 3 min for NeuS reconstruction + 10s for texture refinement)

### Loss functions

- **Standard diffusion noise-prediction loss** on the multi-view latents
- **L_regress = MSE(α̃, α) + MSE(f̃, f)** — auxiliary regression loss for EFReg (Eq. 2 of paper)

## Connections to H1-H5

### H1 (2-stage partial+refinement) — INDIRECT PUSHBACK
Era3D is *literally* 2-stage: (a) multi-view diffusion generates 6 views + normals in 1 forward pass, (b) NeuS reconstructs the mesh in 3 min. But the *first* stage is *not* partial-to-complete — it generates *all 6 views in parallel* via multi-view joint distribution, not progressive refinement. So H1's "partial-then-refine" *paradigm* is *not* validated here; H1's "staged generation" *is* validated. For v0 sub-task 1, the 2-stage "diffusion → NeuS" recipe is *confirmed* as the *2024-2025 standard*, but the *partial→complete* mechanism is *not* (v0 sub-task 1 doesn't need it, full-arch synthesis is a complete problem not a partial-completion problem).

### H2 (latent diffusion > direct) — STRONG DIRECT SUPPORT
Era3D is built on **SD2.1-unclip** (a latent diffusion model), inheriting the H2 paradigm from Wonder3D 063/118, SV3D 117, CAT3D 113, L4GM 114, Bolt3D 116. The 6-view joint generation in *latent space* (32×32 → 64×64 → 512×512 progressive upscale) is the *canonical* H2 mechanism. For v0 sub-task 1, Era3D confirms that **finetuning a pretrained latent-diffusion backbone is the right strategy** — 30h on 16 H800s is the *cheap* finetune (vs. 5-15 days for from-scratch 3D-diffusion).

### H3 (per-tooth conditioning / inter-tooth awareness) — STRONGEST SUPPORT, NEW MECHANISM
Era3D's **EFReg** is the *killer* H3 mechanism for v0 sub-task 1. The fact that *regressing (focal_length, elevation) from the UNet's middle-block AvgPool(H) and feeding them BACK as denoising conditioning* yields **3.8× more accurate pose estimation than DINOv2-pretrained regressors** is the *cleanest* H3 evidence in the reading list. For v0 sub-task 1 (full-arch synthesis from a 2D intra-oral photo):
- **The exact analog of "elevation+focal" is "viewpoint + scanner calibration"** (Primescan vs Trios vs iTero have different FOV, different optical center, different magnification)
- **Adopt EFReg**: the v0 sub-task 1 multi-view diffusion backbone should regress (scanner-FOV, scanner-calibration-params) from the UNet's middle-block features and condition the denoising on these
- **The 3.8× accuracy gain is a free-lunch for v0**: just like Era3D learns to "rectify" perspective to orthogonal, v0 learns to "rectify" scanner-specific perspective to canonical intra-oral frame

### H4 (implicit SDF > explicit point/mesh) — INDIRECT PUSHBACK
Era3D outputs *explicit* mesh via NeuS, NOT implicit SDF — but the mesh is *extracted from a learned implicit SDF* (NeuS = neural SDF + rendering loss). So H4 is *partially* supported: implicit SDF is the *intermediate* representation for mesh extraction, but the *output* is explicit mesh. For v0, the v0 stack's H4 stance is *confirmed*: implicit SDF for v0 sub-task 2 (crown) is right, but for v0 sub-task 1 (full-arch) we output *mesh* (or 3DGS) for downstream use, not SDF.

### H5 (synthetic pretrain + finetune) — STRONGEST SUPPORT, MULTI-SCANNER EVIDENCE
Era3D is trained on **Objaverse-rendered perspective images at 5 different focal lengths {35, 50, 85, 105, 135}mm** — this is the *exact* H5 mechanism: pretrain on *diverse* synthetic perspectives so the model can handle *arbitrary* real-world perspectives at inference. For v0:
- **Adopt multi-scanner-focal-length training**: render synthetic intra-oral views at 5-10 different FOVs/calibrations, train the multi-view diffusion on this *diverse* mixture
- **Adopt the *test-time camera-pose prediction* paradigm**: the v0 inference pipeline predicts the scanner FOV/calibration from the input image (via EFReg) and conditions the denoising on the prediction, *exactly* like Era3D predicts (α, f)
- **The 3.8× accuracy gain over DINOv2 baselines is the killer evidence** that *learned* camera-pose-from-diffusion-features is *better* than *external* pose estimators, the *right* v0 H5 mechanism

## Surprises / interesting things buried in section 4

1. **RMA quality matches dense attention** (Table 4: row-wise CD 0.0232 vs dense 0.0239, *better* on 3/5 metrics) — the *cheaper* attention is *not* worse, it actually *focuses more* on valuable tokens because the row-constrained attention is *less diluted* by irrelevant cross-view tokens. This is a *counterintuitive* result that the paper explains as "row-wise attention reducing the number of attention tokens, allowing the model to focus more on valuable tokens."

2. **At 512² without xFormers, RMA gives 30× memory + 100× runtime** (Table 3: 1.66GB / 2.23ms vs 35.32GB / 220.41ms) — but the paper's abstract headline is *only* "12×" because that's the xFormers-comparison. The *raw* efficiency is *much* better.

3. **EFReg is a *joint* regression-and-conditioning scheme**, not just regression — the predicted (α̃, f̃) are *added to the diffusion timestep embedding in every residual block* (Sec 3.2, "the regressed elevation and focal length ... are further conditioned to the diffusion process"). This is *not* a post-hoc pose estimator; it's *in-loop* conditioning.

4. **The pose estimation ablation uses DINOv2-vitb14** (not the larger vitl14) as a fair baseline — the smaller backbone is a *deliberate* choice to make the comparison fair against Era3D's ~1.5B UNet.

5. **Era3D is the first paper to *explicitly* address the camera-intrinsic-mismatch problem** (Sec 1) — prior works (Wonder3D, SyncDreamer, Zero123++, MVDream) *all* assume fixed focal length at training, leading to *silent* failure modes on real-world perspective inputs. Era3D is the *first* to *measure* this failure mode and *fix* it.

6. **The 6 view azimuth offsets are {β, β±45°, β±90°, β+180°}** — *not* the more common {0, 60, 120, 180, 240, 300} (uniform). The choice to *align one view with the input azimuth* is *deliberate* so the input view can be used as a *strong* conditioning signal. The ±45° / ±90° / 180° pattern is *optimized* for top-down reconstruction.

7. **Era3D's "instant-nsr-pl" mesh extraction is 3 minutes** for the full mesh — the *bulk* of inference time is *not* the multi-view diffusion (13s) but the NeuS reconstruction (180s). For v0 chairside, this is the *bottleneck* — must either accept 3-min mesh extraction (acceptable for crown design workflow) or replace NeuS with a faster reconstruction (e.g., 3DGS).

8. **Texture refinement takes 10s** (separate from NeuS) — a *post-hoc* texture refinement pass that uses the multi-view normals as a prior. The authors don't elaborate on this in the main paper, but it's the *secret* to Era3D's high SSIM (0.837 vs Wonder3D's 0.811).

9. **Era3D's "limitation" (Sec 5) is *thin structures* and *open surfaces*** — *not* the camera-mismatch (solved), *not* the resolution (solved), but the *neural-SDF substrate's* inability to represent thin/open geometry. The authors suggest *future* integration with 3DGS — exactly the v2 sub-task 1 direction noted in the 121 Neuralangelo note.

10. **No explicit cross-view consistency loss** in the training objective — the multi-view consistency is *learned implicitly* via the RMA attention pattern + the canonical-camera setup. The 6 views are *forced* to be consistent because they share the same row-wise attention pattern, not because there's a loss term enforcing it.

11. **The 6-view setup is *fixed*** (not variable N) — every Era3D inference generates exactly 6 views. This is a *deployment* simplification: v0 doesn't need to choose N at inference time, it's a hyperparameter baked into the architecture.

12. **Era3D's "regress-and-condition" scheme can be extended to *any* camera parameter** — the paper only shows (α, f), but the same architecture can regress (β, principal-point-x, principal-point-y, radial-distortion, etc.). For dental, this could include (prep-margin-elevation, gum-line-angle, tooth-class-as-pose-embedding) as additional conditioning signals.
