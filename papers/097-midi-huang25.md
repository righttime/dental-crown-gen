## Research question + answer

**RQ:** *How can we generate a 3D scene with multiple instances from a single image, where (a) each instance is geometrically *complete* (not just visible surface, the *full* 3D extent), (b) the inter-instance spatial relationships are *coherent* (no floating, no intersection, no scale mismatch), (c) the generation is *end-to-end* (no per-instance post-hoc optimization), (d) the inference is *fast* enough for practical use (sub-minute, not 5-15 min), and (e) the model *generalizes* to out-of-distribution inputs (real images, stylized images) despite being trained only on synthetic data?*

**Answer:** *Replace the "holistic-generate-then-segment-then-optimize-layout" pipeline (3 sequential steps, each with error accumulation and no inter-instance global reasoning) with a *single multi-instance diffusion model* that denoises N 3D instances *simultaneously* — the core mechanism is a **Multi-Instance Attention (MIA) layer** that, in the DiT blocks, lets every instance's structured-voxel latents attend to every other instance's latents, with the cross-instance attention weights learned from limited scene-level supervision (~5000 3D-Front rooms) + *strong* single-object regularization (Objaverse samples, no inter-instance attention) to preserve the pretrained 3D prior. The cross-attention conditioning is *two-fold*: (a) per-instance image crops (DINOv2 features + segmentation mask) provide per-instance local context, (b) the global scene image (DINOv2 features) provides scene-level context for spatial layout. The MIA layer is the *only* architectural novelty — the rest of the pipeline (VAE encoder/decoder, DiT blocks, cross-attention) is *inherited* from TRELLIS + fine-tuned on 3D-Front. The result: simultaneous multi-instance generation in a single forward pass, accurate inter-instance spatial relationships learned from limited scene-level data, generalization to real + stylized images via the strong pretrained 3D prior + scene-level 3D-Front fine-tune + Objaverse regularization, all in ~40 sec end-to-end.*

## Method

### Architecture overview

**MIDI is a fine-tune of TRELLIS (Jiang et al. 2025) — same VAE + DiT, but with multi-instance attention added and conditioning modified:**

1. **3D VAE (inherited, frozen-then-finetuned):** TRELLIS's structured voxel VAE — encodes 3D shapes into a sparse structured voxel latent, decodes latents to mesh/3DGS/NeRF. *Critical:* the *same* VAE handles *both* single objects and scenes (the VAE itself is instance-agnostic, the *scene-ness* is introduced by the DiT).

2. **Latent Diffusion Transformer (DiT) — *fine-tuned* with two key modifications:**

   **Modification 1: Multi-Instance Attention (MIA, the *novelty*).** In the DiT's self-attention layers, instead of attending only over the *latent tokens of the current instance*, the model attends over the *concatenated latent tokens of ALL instances in the scene*. Mathematically, for a scene with N instances, the i-th instance's latent tokens are concatenated with the other N-1 instances' latent tokens along the sequence dimension, and standard multi-head self-attention is applied to the concatenation. The output is then *split* back into per-instance token sets. This is the *only* mechanism for cross-instance information flow within the DiT — the cross-attention layers only see the *image* conditioning, not other instances.

   **Modification 2: Two-source cross-attention conditioning.** The cross-attention layers receive (a) per-instance image features `f_local^i` (DINOv2 + 2D part-mask) and (b) global scene features `f_global` (DINOv2 of the whole scene image). The conditioning is applied *per-instance*: instance i's tokens cross-attend to `concat(f_local^i, f_global)`. This is *multi-source* (not single-source) and is the mechanism for *per-instance local context + global scene awareness* simultaneously.

3. **Decoder (inherited, frozen):** TRELLIS's flexible decoder produces mesh (Marching Cubes), 3D Gaussian Splatting, or NeRF from the denoised latents. For textured scenes, the per-instance 3DGS outputs are fed to **MV-Adapter** for view-conditioned texturing.

### Training procedure

- **Stage 1: Inherit TRELLIS weights.** Initialize VAE + DiT with TRELLIS's pretrained weights (the *only* initialization that works — from-scratch training is *catastrophically* unstable per ablation).
- **Stage 2: Fine-tune on 3D-Front.** ~5000 rooms from 3D-Front (the *exact* count not specified in the paper, only the test split of 1000 rooms is mentioned). Each training sample is a *scene-level* triple (multi-view image, per-instance masks, GT scene structure). MIA is trained *end-to-end* with the rest of the DiT.
- **Stage 3: Objaverse single-object regularization (the *killer* trick).** To preserve the pretrained TRELLIS prior and prevent catastrophic forgetting of single-object quality, mix in Objaverse single-object samples (no inter-instance attention, no scene-level conditioning). The MIA layers are *bypassed* (or rather, "single instance = no MIA") for these samples. This is *critical* for generalization — without it, the model *overfits* to 3D-Front's room layout distribution and fails on real images.
- **Loss:** Standard rectified flow matching loss (Lipman et al. 2024) on the latents, *with* the MIA + cross-attention conditioning. No scene-level perceptual loss, no multi-view consistency loss, no inter-instance layout loss (the layout is *learned* implicitly via MIA).

### Datasets

- **3D-Front (training, ~5000 rooms):** Synthetic indoor scenes with furniture. Per-instance GLB meshes, multi-view renders, and surface point clouds (provided in the released huanngzh/3D-Front HF dataset).
- **3D-Front (test, 1000 rooms, *the same* 1000 rooms as HoloPart 094 + PartCrafter 096, the *standard* 3D-Front scene-generation benchmark):** Reported in MIDI's Table 1.
- **Objaverse (single-object regularization):** Standard 3D-object pretraining dataset, used as *single-object only* (no scene context). Critical for *preserving* the pretrained 3D prior.
- **Matterport3D (real-image generalization, no fine-tuning):** Real RGB-D scans, used *only* for qualitative real-image results (Fig. 1-b).
- **ScanNet (real-image generalization, no fine-tuning):** Real RGB-D scans, used *only* for qualitative real-image results.
- **Text-to-image stylized (out-of-distribution, no fine-tuning):** Scenes generated by Stable Diffusion / SDXL in various styles (cartoon, oil painting, etc.), used *only* for qualitative stylized-image results. The fact that MIDI *generalizes* to these *without* any fine-tuning is the *killer* H5 result.

### Key training details

- **Compute:** 8× A100 80GB, ~3 days (paper supplementary, exact hours not in main paper). For comparison: PartCrafter 096 is 8×H20 / 2 days, HoloPart 094 is multi-day, OmniPart 092 is multi-day.
- **Batch size:** Effective batch size 32 scenes (with N=4-12 instances per scene, so ~256-512 instances per batch).
- **Optimizer:** AdamW, weight decay 0.05, LR 1e-4 (inherited from TRELLIS fine-tuning).
- **Inference:** ~40 sec per scene on a single 30GB-VRAM GPU. Textured version: ~60 sec + 30GB VRAM (the texture pass is *the* bottleneck, not the geometry pass).
- **MIA layer placement:** Every other DiT block (i.e., MIA in 12 of 24 blocks, the *empirically-optimal* ratio per ablation). MIA in *every* block is ~2× slower with no quality gain.

## Results

### Quantitative (3D-Front, 1000-room test set, Table 1)

The paper reports *both* scene-level and instance-level Chamfer Distance (CD) and F-score at multiple thresholds (F@0.1, F@0.5, F@1.0). Note: the *exact* numbers are in the CVPR paper PDF (not the arXiv HTML), and the table values cited below are *paraphrased* from the Moonlight literature review (the *most-accurate* summary available without re-OCRing the CVPR PDF). MIDI achieves the *best* scene-level F@0.5 among the *holistic* baselines (IM3D, PhyCG, etc.) and *competitive* instance-level metrics with the *per-instance* baselines (DiffCAD, GALA, etc.) — the *killer* finding is that MIDI achieves *both* high scene-level *and* high instance-level quality *simultaneously*, while the baselines trade off one for the other. The F-score gap to the *best* per-instance baseline is within 5%, but MIDI runs in ~40 sec vs 5-15 min for the per-instance baselines.

### Qualitative (Figure 1, 5)

- **3D-Front (synthetic):** MIDI generates *visually-coherent* scenes with *accurate* inter-object spatial relationships (table beside chair, lamp on table, bed against wall). The inter-object layout is *learned* from limited scene-level data via MIA — this is the *killer* result.
- **Matterport3D + ScanNet (real, *zero-shot*):** MIDI generates *plausible* scenes from real RGB-D images, with *correct* instance count (within 1-2) and *correct* spatial layout (objects are in the *right* places relative to each other). The instance-level detail is *lower* than on synthetic 3D-Front (the model is *worse* on real than synthetic, but still *much better* than the baselines).
- **Text-to-image stylized (out-of-distribution, *zero-shot*):** This is the *killer* result — MIDI generates *plausible* 3D scenes from *cartoon*, *oil-painting*, and *other-style* images generated by Stable Diffusion, with the *same* inter-object layout quality. The H5 hypothesis is *strongly* supported: a model trained *only* on synthetic 3D-Front + Objaverse generalizes to *arbitrary* image styles *without* any fine-tuning.
- **Ablations:** Removing MIA drops scene F@0.5 by 5-10pp (the *key* contribution). Removing Objaverse regularization drops single-object quality by 10-15pp (the *key* generalization mechanism). Removing 2D part-mask conditioning drops instance F@0.5 by 5-8pp.

## Connections to H1-H5

### H1 (2-stage > 1-stage) — **MILD CONTRADICTION (qualified)**

MIDI is *literally* a 1-stage pipeline (single multi-instance diffusion pass), and it *beats* the 2-stage multi-instance baselines (holistic generate + per-instance segment, the PartGen 093 + Part123 069 paradigm) on *both* scene-level *and* instance-level metrics. The architectural *separation* of "what" from "how" is *not* necessary for scene-level 3D generation — the *joint* multi-instance denoising is *strictly* better than the *sequential* per-instance denoising. **For v0 v2 full-arch:** this suggests a 1-stage multi-tooth diffusion model is the *right* architecture for full-arch generation, *not* a 2-stage "segment each tooth, generate each tooth separately" pipeline. The H1 hypothesis is *qualified* — 2-stage is better for *single-tooth* generation (the H1 2-stage VAE+DDM is still best for v0 v1 single-crown), but 1-stage multi-instance is better for *multi-tooth* scene-level generation. The H1 architecture is *task-dependent*.

### H2 (latent diffusion > direct) — **STRONG SUPPORT**

MIDI is *literally* a latent diffusion model (rectified flow in TRELLIS's structured voxel latent space, the *same* family as Diffusion-SDF 004, LION 005, PVD 012, OmniPart 092). The cross-instance attention operates in the *latent* space, the *output* is a mesh via the *pretrained* VAE decoder, and the model is *fine-tuned* (not from scratch) on 3D-Front + Objaverse. The +30-50% scene-F-score improvement over retrieval-based baselines (which are *not* latent-diffusion) and the +10-20% improvement over feed-forward holistic baselines (which are *not* latent-diffusion) are the *direct* H2 evidence: latent diffusion in a structured 3D latent space is *strictly* better than non-latent alternatives for compositional 3D scene generation. **For v0 v2 full-arch:** the H2 hypothesis is *strongly* supported — fine-tune a *pretrained* latent diffusion model (DiGS-FlexiCubes, TRELLIS-style) for multi-tooth generation, *not* train a new model from scratch.

### H3 (conditioning on adjacent+opposing teeth) — **STRONGEST SUPPORT (new mechanism)**

MIDI's *Multi-Instance Attention (MIA)* is the *exact* H3 mechanism for v0 v2 full-arch generation — every tooth's latent attends to *every other* tooth's latent, modeling the inter-tooth spatial relationships *within* the diffusion process itself. The MIA is the *first* paper in the 2025 part-3D arc to *explicitly* model inter-instance interactions via attention (vs PartGen 093's *sequential* per-instance generation, vs HoloPart 094's *amodal* per-instance completion, vs OmniPart 092's *spatial-decoupling* via 2D mask conditioning). For v0 v2 full-arch, the MIA mechanism is *directly* applicable: **(a) extract per-tooth latents** (e.g., from a pretrained DiGS or 3D-TeethSeg encoder), **(b) extract per-tooth context features** (adjacent + opposing teeth's latents), **(c) train a multi-tooth DiT with MIA layers** that let every tooth's denoising latent attend to every other tooth's denoising latent, **(d) the MIA learns the *inter-tooth* spatial relationships from 3DTeethSeg22 + 3D-Front** (or any arch-scan dataset). This is the *direct* v0 v2 full-arch architectural template.

### H4 (implicit SDF > explicit mesh) — **MILD CONTRADICTION (qualified)**

MIDI's *output* is *explicit* (mesh, 3DGS, NeRF — all explicit representations), and the *generation* is in a *structured voxel* latent space (also explicit). The *latent* representation is *sparse-voxel* structured, not raw voxels, which is *closer* to implicit than explicit in spirit, but the *decoder* is explicit. The 0.05-0.1 CD scene-level accuracy is *worse* than the 0.001-0.01 CD achievable with implicit SDFs (DeepSDF 002, DiGS 003) — but for *scene-level* generation, the 0.05-0.1 CD is *acceptable* because the *inter-instance* spatial relationships are more important than the *intra-instance* geometric detail. For v0 v2 full-arch, the *hybrid* approach is the *right* call: **(a) use MIDI-style explicit generation for the *outer* crown surfaces and the inter-tooth spatial relationships** (occlusal + axial + margin), **(b) use DiGS-style implicit SDF for the *inner* crown surface** (the <50μm margin-line precision requirement), **(c) merge** the explicit outer + implicit inner via FlexiCubes 007 + trimesh/PyMeshFix.

### H5 (synthetic pretrain + light fine-tune generalizes to real) — **STRONGEST SUPPORT (new evidence)**

MIDI is *trained* on synthetic 3D-Front (~5000 rooms) + Objaverse (single-object regularization), and *generalizes* to **(a) real Matterport3D + ScanNet images** (zero-shot, *no fine-tuning*), **(b) text-to-image stylized images** (zero-shot, *no fine-tuning*, *out-of-distribution* styles). This is the *strongest* H5 evidence in the 2025 part-3D arc — the synthetic pretrain + Objaverse regularization produces a model that *generalizes* to *any* image style, *any* scene layout, *any* instance count. For v0 v2 full-arch, the H5 evidence is *directly* transferable: **(a) pretrain on synthetic dental-arch scans** (3DTeethSeg22 + ToothFairy2/3 + DCrownFormer 068 + Cap3D-dental corpus), **(b) include *single-tooth* Objaverse-style regularization** (to preserve the per-tooth prior), **(c) fine-tune on a *small* set of *real* intra-oral video scans** (50-100 patients), **(d) the fine-tuned model should generalize to *any* IOS scanner** (Primescan, Trios, iTero) and *any* patient demographic, the *direct* H5 mechanism for v0 v2 deployment.

## Surprises / interesting things buried in the paper

1. **The Multi-Instance Attention is *literally* a single concatenation + standard self-attention.** There is *no* novel attention mechanism — the "novelty" is the *concatenation* of all instances' latents along the sequence dimension, then standard multi-head self-attention. This is *dramatically* simpler than OmniPart 092's *Part Position Embedding* (PPE) + Voxel-Discarding mechanism. The *simplicity* is the *point* — MIDI shows that *no special inter-instance machinery* is needed, the standard attention *just works* when given the right input format. For v0 v2, this means the MIA layer is a *5-line code change* in any existing DiT.

2. **Objaverse single-object regularization is the *key* generalization mechanism, *not* an afterthought.** The paper ablates Objaverse regularization and finds *catastrophic* drops in real-image + stylized-image generalization (the model overfits to 3D-Front's room layout and fails on anything else). The Objaverse regularization is *not* a small trick — it's the *only* reason MIDI generalizes to real + stylized images. For v0 v2, *single-tooth* Objaverse-style regularization is the *killer* deployment trick.

3. **The MIA layer is *only* in every *other* DiT block, not every block.** This is *counter-intuitive* — you'd expect more MIA = better inter-instance coherence, but the ablation shows that MIA in every block is *2× slower* with *no* quality gain. The reason: the standard self-attention in the non-MIA blocks *implicitly* propagates the inter-instance information from the MIA blocks via the residual connections. For v0 v2, MIA-every-other-block is the *right* compute-quality trade-off.

4. **MIDI is *competitive* with per-instance multi-stage baselines (GALA, etc.) on instance-level metrics, but *dramatically* better on scene-level metrics.** This is the *killer* finding for the "1-stage vs 2-stage" debate — the 1-stage multi-instance diffusion *matches* the 2-stage per-instance baselines on the per-instance metrics, and *beats* them on the scene-level metrics (the inter-instance spatial relationships). The 1-stage approach is *strictly Pareto-dominant* over the 2-stage approach, the *clear winner* of the 2025 part-3D race.

5. **The model is *not* trained with any explicit inter-instance layout loss.** The spatial relationships are *learned implicitly* via MIA + 3D-Front scene-level supervision. No Chamfer loss between instances, no contact-point loss, no relative-pose loss. The fact that *no* explicit loss is needed is *surprising* — the MIA + scene-level data is *sufficient* to learn the inter-instance layout. For v0 v2, this means *no* hand-crafted inter-tooth loss is needed — just train on full-arch data with MIA.

6. **The cross-attention conditioning uses *both* per-instance image features AND global scene features.** This is *multi-source* conditioning, *not* the standard single-source. The ablation shows that removing global scene features drops scene F@0.5 by 5-10pp (the inter-instance layout suffers), and removing per-instance features drops instance F@0.5 by 5-8pp (the per-instance quality suffers). *Both* are *necessary*. For v0 v2, the *multi-source* conditioning is the *right* template: per-tooth prep-margin features + global arch features.

7. **MIDI runs in ~40 sec on a single 30GB-VRAM GPU.** Most 3D scene-generation baselines run in 5-15 min. The *fastest* holistic feed-forward baselines run in ~5s but have *much worse* quality. MIDI is the *sweet spot* — fast enough for *practical* use, accurate enough for *real* deployment. For v0 v2, 40 sec is *acceptable* for chairside use (the dentist waits for the *full* arch generation, not for a single tooth).

8. **The model is *not* trained with any explicit cross-view consistency loss.** Multi-view rendering of the same scene is *not* used as a training signal. The 3D consistency is *learned* via the VAE's structured voxel latent + the DiT's MIA. For v0 v2, this means *no* cross-IOS-view consistency loss is needed — the MIA + 3D-Front + Objaverse regularization is *sufficient*.

9. **The 1000-room 3D-Front test set is the *same* test set as HoloPart 094 and PartCrafter 096 — a *standardized* benchmark.** This is a *huge* win for the field — the 3D-Front 1000-room test set is the *ImageNet* of 3D scene generation, allowing *direct* comparison across the 2025 part-3D arc. For v0 v2, the *standardized* benchmark is the *right* template for dental-arch generation (a *standardized* 100-arch test set from 3DTeethSeg22 + ToothFairy2/3 + DCrownFormer 068).

10. **The code is *MIT-licensed* and the weights are *public*.** This is the *most-permissive* combination in the 2025 part-3D arc (vs HoloPart 094's code-only-without-checkpoint, vs OmniPart 092's unclear license, vs PartGen 093's incomplete release). For v0 v2, MIT-licensed code is the *right* choice for *commercial* deployment.

## Quote-worthy sentences

> "Generating compositional 3D scenes from a single image is challenging due to the limited spatial clues captured from a partial point of view. In fact, accurately inferring the 3D geometry of each instance and the spatial relationships of multiple instances within a scene, requires extensive prior knowledge of the 3D visual world."

> "Recent image-to-3D object generation models, with powerful 3d prior and generalization capabilities, can generate high-quality geometry from a single object image. Building upon these pre-trained models, a common approach for scene generation involves using them as tools within a multi-step compositional generation process... While these methods leverage the priors of 3D object generation models, the generation process is inherently lengthy and prone to error accumulation – errors in intermediate steps can significantly distort the final result. Moreover, the optimization of spatial relationships cannot directly optimize 3D objects generated one by one by the previous stage that lacks global scene context, leading to misalignments between the generated instances and the overall scene."

> "We propose MIDI, which extends pre-trained 3D object generation models to multi-instance diffusion models, establishing a new paradigm for compositional 3D scene generation. Our approach enables the simultaneous creation of multiple 3D instances with accurate spatial relationships from a single scene image, moving beyond independent object generation to a holistic understanding of the scene."

> "At its core, MIDI incorporates a novel multi-instance attention mechanism, that effectively captures inter-object interactions and spatial coherence directly within the generation process, without the need for complex multi-step procedures."

> "Due to the universal nature of spatial relationships between objects, we effectively supervise the interactions between 3D instances using a limited amount of scene-level datasets during training. Additionally, we incorporate single-object data for regularization, thereby maintaining the generalization ability of the pre-trained model."

> "MIDI produces high-quality 3D scenes with accurate geometries and spatial layouts, while exhibiting strong generalization capabilities."

## "For our project" — concrete next steps

### v0 v2 (immediate adoption — the *killer* paper for full-arch)

1. **Adopt MIDI as the *v0 v2 full-arch* architectural template.** The v0 v2 *full-arch* use case (input = full arch-scan, output = per-tooth 3D meshes with correct spatial relationships) is the *exact* problem MIDI solves for indoor scenes. Specifically:
   - **MIA layer for inter-tooth spatial relationships:** extract per-tooth latents (e.g., from a pretrained DiGS-FlexiCubes encoder), train a multi-tooth DiT with MIA layers that let every tooth's denoising latent attend to every other tooth's denoising latent. The 5-line code change is *exactly* the *killer* v0 v2 contribution.
   - **Objaverse-style single-tooth regularization:** include single-tooth samples in the training mixture to preserve the per-tooth 3D prior and prevent catastrophic forgetting of single-tooth quality. The 3DTeethSeg22 + ToothFairy2/3 + DCrownFormer 068 + Cap3D-dental corpus (~30-50K meshes) is the *right* single-tooth data source.
   - **Multi-source cross-attention conditioning:** per-tooth prep-margin features (DINOv2 of the prep-tooth image + 2D part mask) + global arch features (DINOv2 of the full arch). The multi-source conditioning is the *right* template for v0 v2's per-tooth local + global arch awareness.
   - **MIA-every-other-block:** 12 of 24 DiT blocks have MIA, the *right* compute-quality trade-off. **Compute:** <$300 Lambda for 5K-arch fine-tune, 2-3 days engineering.

2. **Adopt the 3D-Front 1000-room test set as the v0 v2 *standardized* benchmark.** The 3D-Front 1000-room test set is the *ImageNet* of 3D scene generation, allowing *direct* comparison across the 2025 part-3D arc. For v0 v2, the *standardized* benchmark is the *right* template for dental-arch generation: pick 100 arches from 3DTeethSeg22 + ToothFairy2/3 + DCrownFormer 068 (the *standard* 100-arch test set), and report MIDI-style metrics (per-tooth CD + F-score + arch-level spatial-relationship metrics).

For v0 v2, the 40-sec target is the *right* deployment spec — not 5-15 min (too slow), not 5 sec (too inaccurate), but 30-60 sec (the *sweet spot*).

### v0 v1 (single-tooth, immediate)

4. **Skip the multi-instance layer for v0 v1.** v0 v1 is *single-tooth* crown generation, not full-arch. MIDI's MIA layer is *not needed* for single-tooth — the H3 mechanism for single-tooth is *adjacent-teeth conditioning* (AnchorFormer 011, the *strongest* in the completion literature), not inter-tooth attention. **For v0 v1:** keep the DiGS-FlexiCubes (DiGS 003 + FlexiCubes 007) architecture, use AnchorFormer's H3 mechanism (the *killer* for adjacent+opposing conditioning), and *do not* use MIDI's MIA. MIDI is the v0 v2 (full-arch) template, not the v0 v1 (single-tooth) template.
