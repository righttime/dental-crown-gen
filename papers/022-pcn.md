## TL;DR

**PCN is the *first* learning-based method to do 3D shape completion directly on raw point clouds (no voxelization) and the *first* to combine a fully-connected coarse decoder with a FoldingNet-based fine decoder in a single coarse-to-fine network trained end-to-end.** The architecture is the simplest completion backbone in our reading list — 2-layer stacked PointNet encoder (1024-dim global feature) + 1024-point coarse output (FC) + 16× folding per coarse point → 16384-point detailed output — and it achieves a **6.85M-param, 0.0012s/shape inference** model that beats volumetric 3D-EPN (52.4M params) on ShapeNet completion (CD 0.00964 vs 0.02015, **−52%**) and transfers zero-shot to KITTI LiDAR cars with no fine-tuning. **For our project, PCN is the v0 lower-bound baseline** — the simplest, cheapest, fastest completion model in our reading list, and the one against which we should quantify the marginal value of AnchorFormer, SnowflakeNet, SeedFormer, and PVD's "free points" trick.

## Research question

> Voxel-based completion methods (3D-EPN, Han et al. high-res shape completion) suffer from cubic memory cost of 3D grids, lossy discretization, and limited output resolution. **Can we complete partial 3D shapes *directly* on point clouds — permutation-invariant, memory-efficient, no intermediate voxelization — while still generating dense (16k+ point) outputs that capture fine geometric detail?**

Their answer: **yes, by combining the strengths of two existing point-cloud decoders — the global-geometry-aware FC decoder (Achlioptas et al. 2017) and the local-surface-aware FoldingNet decoder (Yang et al. 2017) — in a single coarse-to-fine architecture.** The FC head predicts a sparse (1024-point) coarse output that captures global shape; the Folding head then deforms a tiny 4×4 grid (r=0.05) per coarse point into a 16-point local patch, producing 16384 detailed points. Trained end-to-end with a sum of two CD losses (coarse + fine), PCN outperforms voxel, FC-only, and Folding-only baselines on ShapeNet and transfers zero-shot to real KITTI LiDAR.

## Method

**Encoder: stacked PointNet (Sec 4.1).** Two stacked PN layers, not PointNet++:
- **PN₁:** 2-layer shared MLP (128, 256 units) with ReLU → pointwise maxpool → 256-dim global feature `g`
- **PN₂:** concatenate `g` to each point's PN₁ feature → 2-layer shared MLP (512, 1024 units) with ReLU → pointwise maxpool → **1024-dim global feature `v`**

The encoder inherits PointNet's permutation invariance and noise robustness. **The choice of stacked-PN over PointNet++ is deliberate and counterintuitive** — Fig 3 shows PN2 (PointNet++) loses to stacked-PN on this task. The reasoning (Sec 5.2): local pooling depends on stable kNN neighborhoods, which are unstable for *partial* point clouds with sparse / unevenly distributed points. **This is a direct H5 precedent: synthetic-pretraining is robust only with global-pooling encoders, not hierarchical ones.**

**Decoder: multistage coarse-to-fine (Sec 4.2).**
- **Stage 1 (coarse, FC):** 3 FC layers (1024, 1024, 1024·3 units) → reshape to (1024, 3) → `Y_coarse ∈ ℝ^{1024×3}`
- **Stage 2 (detail, Folding):** For each coarse point `q_i`:
  - Build a `u×u` zero-centered 2D grid (u=4, scale r=0.05) → `G ∈ ℝ^{16×2}`
  - Concatenate each row of `G` with `q_i` and the global feature `v` → 16 concatenated vectors
  - Pass through 3-layer shared MLP (512, 512, 3 units) with ReLU → `Q ∈ ℝ^{16×3}` (local patch in world coords, since `q_i` was concatenated in directly)
  - Combine all 1024 patches → `Y_detail ∈ ℝ^{16384×3}`

**Key observation (Sec 4.2):** the FC decoder captures *global geometry* (sparse set of well-spread points), the Folding decoder captures *local surface continuity* (smooth 2D-manifold-like patches). The combination outperforms either alone on both CD (FC wins) and EMD (PCN-EMD wins) — the coarse step prevents the Folding points from collapsing into a single local cluster, and the folding step prevents the FC points from being over-concentrated in any one region (a known FC failure mode visible in Fig 9).

**Loss (Sec 4.3, Eq 3):**
```
L = d₁(Y_coarse, Y_gt^sampled) + α · d₂(Y_detail, Y_gt)
```
where `Y_gt^sampled` is the GT point cloud uniformly subsampled to 1024 points. Two variants:
- **PCN-CD:** `d₁ = d₂ = CD` (Chamfer Distance, O(n log n) via KD-tree)
- **PCN-EMD:** `d₁ = EMD` (Earth Mover's Distance, O(n²) iterative `(1+ε)` approximation), `d₂ = CD`

EMD is too expensive for 16384 points during training. The paper's CD-vs-EMD illustration (Fig 5) is canonical: **CD concentrates error at missing/corner regions, EMD is uniform — CD penalizes missed regions, EMD penalizes density difference.** For our project, CD is the right metric (we care about missing prep-margin data more than uniform density).

**Training (Sec 5.1):** Adam, LR 1e-4, batch 32, 50 epochs, LR decay 0.7 every 50K iters. ShapeNet 8 categories (airplane, cabinet, car, chair, lamp, sofa, table, vessel), 30974 models, 8 random viewpoints per model, 100 val / 150 test held out. Complete point clouds = 16384 points uniform-sampled; partial point clouds = back-projected from 2.5D depth images. **Note the deliberate choice of depth-image partial inputs (not subsets of complete) to match real sensor distributions** — a critical H5 detail.

## Results

**ShapeNet completion (Tables 4–5, 8 categories, 150 test shapes per category, CD/EMD per point, lower=better):**

| Method     | Params  | CD-Avg   | EMD-Avg  |
|------------|--------:|---------:|---------:|
| 3D-EPN     | 52.4M   | 0.020147 | 0.081785 |
| FC         | 53.2M   | 0.009799 | 0.171280 |
| Folding    | 2.40M   | 0.010074 | 0.228015 |
| PN2        | 6.79M   | 0.013999 | 0.101445 |
| **PCN-CD** | **6.85M** | **0.009636** | 0.087142 |
| **PCN-EMD**| **6.85M** | 0.010021 | **0.064044** |

PCN-CD wins CD-Avg (best in 5/8 categories), PCN-EMD wins EMD-Avg by a wide margin. **Note: FC and Folding each have a fatal failure mode** — FC's points over-concentrate in dense regions (high EMD 0.17), Folding's points are over-spread with floating artifacts (high EMD 0.23). PCN's multistage design is what fixes both.

**Unseen categories (Tables 6–7, 150 models from 8 held-out categories split into "similar" bus/bed/bookshelf/bench and "dissimilar" guitar/motorbike/skateboard/pistol):** PCN-CD/EMD still wins on most categories. **The model's performance is not significantly affected even on visually dissimilar categories** (e.g., pistol still gets CD 0.0136, in line with similar-category 0.0142). The shape prior learned from 8 categories generalizes to *all* CAD objects.

**Robustness (Sec 5.2, Fig 6):** Add Gaussian noise (σ=0.01 × depth scale) and random occlusion (0–80% of input points), then evaluate. **CD and EMD degrade only gradually** as occlusion increases, even though the model was *not* trained on occluded/noisy examples. **The learned shape prior acts as a regularizer** — the model "knows" what a complete chair looks like and ignores noisy points.

**KITTI LiDAR transfer (Sec 5.3, Table 2):** PCN trained on ShapeNet cars, evaluated on 2483 partial point clouds from KITTI Velodyne sequences, *no fine-tuning*. Each input has ~440 points on average (some <10), vs ShapeNet partial inputs that have >1000. Three new metrics:
- **Fidelity** 0.028 — avg distance from each input point to its NN in output (input preservation)
- **MMD** 0.0185 — CD between output and the closest ShapeNet car (car-ness)
- **Consistency** 0.0116 — avg CD between completion outputs of the *same* car in consecutive frames (temporal stability)
- **Consistency (input)** 0.0512 — same metric on raw partial inputs

**The 4× consistency gap (0.012 vs 0.051) is the strongest empirical H5 evidence in this paper** — the completed point clouds are *more temporally coherent* across LiDAR frames than the raw partial clouds. The model effectively denoised the partial scans. **This is a stronger H5 precedent than just "transfers without fine-tuning"** — it shows the completed representation is *better* than the raw representation for downstream tasks.

**Inference speed (Sec 5.3):** **0.0012s per shape on a GTX 1080Ti, 2s on an i7-7700 CPU** — the fastest model in our reading list by 10–100×. Real-time capable on the M4 Mac mini even with a PyTorch port.

**Failure modes (Sec 6, Fig 8):** two identified:
1. **Multi-part disconnected objects** (e.g., scissors, table + chair) — model incorrectly connects parts because training data is mostly single-part.
2. **Thin structures** (e.g., lamp wires, chair legs at extreme angles) — points are too sparse for 3D feature extraction, and 2D grid deformation can't replicate thin tubes.

**Architecture ablations (Supp Sec F):**
- **2 stacked-PN layers is the sweet spot** (Fig 13): 1 layer is much worse, 3+ layers give no gain. The model only needs ~360 keypoints in PN₂ to capture shape (Table 3: 1105 input → 101 PN₁ keypoints → 363 PN₂ keypoints, *unsupervised emergence*).
- **Bottleneck 1024 is the largest that fits a single-GPU 11GB** (Fig 14). 2048 would help with multi-GPU training.

**T-SNE of 1024-dim global features (Fig 17):** clusters by *semantic category* with no label supervision. The 8 train categories form visibly distinct clusters. **Emergent categorical structure** — the same observation DiGS (paper 003) makes about its SDF features, and LION (paper 005) makes about its `z₀` latent.

## Hypothesis connections

- **H1 (2-stage VAE + DDM > 1-stage):** **provides the 1-stage baseline**. PCN is single-stage end-to-end, no VAE, no diffusion — the simplest possible completion model. The LION, Diffusion-SDF, SDFusion, PVD, MeshDiffusion, PolyDiff 2-stage wins are *all measured against* PCN-class single-stage baselines. The "delta" that 2-stage architectures claim to add is the marginal value of multi-modal sampling and latent regularization.
- **H2 (latent diffusion > direct):** **deterministic single-pass, no diffusion — the right baseline for LION's +6 1-NNA point gain.** But the more interesting test is: PCN already has an implicit "free points" mechanism (the model just learns to output the right thing for the missing region) — PVD (paper 012) makes this explicit. PCN is the *historical precedent* for partial-to-full point cloud inference; PVD inherits the same architecture and adds diffusion.
- **H3 (conditioning on adjacent+opposing teeth is the H3 mechanism):** **lower bound on H3 — single 1024-dim global feature, no per-region conditioning.** This is *exactly* why PCN struggles on sharp features: the global feature is symmetric in the input order, so it can't preferentially weight "this region is the prep margin, preserve it; this region is the missing crown, generate it." The H3 progression in our reading list: PCN (global) → SnowflakeNet (parent-child local) → SeedFormer (regional seeds) → AnchorFormer (learned anchors). **PCN is the historical lower bound.** For our project, the global 1024-dim feature is *exactly* the wrong conditioning signal — we need the FDI-aware neighbor teeth to be explicitly represented (per the v0 decision to use PVD's "free points" trick, which is H3-faithful without needing an encoder).
- **H4 (implicit SDF > explicit mesh):** **point cloud, not SDF — the right baseline against DiGS (paper 003).** PCN's 16384-point output is competitive on completion metrics (CD 0.0096), but produces a *sparse point cloud*, not a watertight mesh. For 3D printing we need to lift to SDF (DiGS) and extract a mesh (FlexiCubes, paper 007). The PCN→DiGS→FC pipeline is what AnchorFormer→DiGS→FC looks like in our v0 stack, just with a stronger backbone.
- **H5 (synthetic pretrain + light fine-tune generalizes to real):** **STRONGEST support in the reading list at the completion level, *and* strongest evidence beyond "just transfers".** Three pieces of evidence: (i) zero-shot KITTI transfer on extremely sparse LiDAR inputs (~440 points avg, some <10); (ii) the *4× consistency improvement* (output 0.012 vs input 0.051 across frames) — the completed representation is *better* than the raw representation for downstream tasks like ICP registration (Sec 5.4 shows PCN-completed clouds reduce ICP rotation + translation error); (iii) the ShapeNet-8 → 8-unseen-category transfer (CD ~0.014 on dissimilar categories like pistol, similar to seen). PCN is the *first* H5 precedent in the completion sub-field, predating AnchorFormer's +0.133 F1 on unseen categories by 5 years.

## Surprises / interesting things buried in the paper

1. **The CD vs EMD illustration (Fig 5) is the single best visualization in the completion literature** — it makes the abstract metric concrete. For our project, this is the moment to lock in CD as the primary metric (we want to penalize missing prep-margin regions) and use EMD only as a secondary density-regularizer. The visualization is the citation for why.

2. **Stacked-PN beats PointNet++ on partial point cloud completion (Fig 3, PN2 vs PCN-CD row).** This is counterintuitive — local hierarchical pooling is *strictly more powerful* on full shapes, so why does it lose on partial shapes? The paper's reasoning (Sec 5.2) is that local pooling depends on stable kNN neighborhoods, which are unstable for sparse / unevenly distributed partial scans. **This is a deep H5 lesson for our project: do NOT use PointNet++ as the encoder for partial arch point clouds. The local pooling will be noisy on sparse prep boundaries.** Use stacked-PN, or use the geometrically-conditioned encoders from AnchorFormer / SnowflakeNet (both use the partial input directly, not via PointNet++ set-abstraction).

3. **The "keypoint count" (Table 3): 1105 input points → 101 keypoints in PN₁ → 363 keypoints in PN₂.** The first PN layer abstracts to ~100 keypoints (rough outline); the second refines to ~360 (fine surfaces). **This coarse-to-fine keypoint selection emerges without supervision.** This is the *PointNet* inductive bias quantified: "as long as these keypoints are preserved, the learned features won't change" (Sec F). The robustness to noise (Fig 6) is a direct consequence — drop 50% of input points, the ~100 PN₁ keypoints are still the same.

4. **The folding grid is tiny** — u=4, r=0.05 means a 4×4=16-point patch per coarse point, in a 0.1×0.1 local window. The MLP that does the deformation is 3 layers of 512-512-3 = ~790K params. **For tooth cusps (1mm-scale features on a 30mm arch), this resolution is borderline** — it'll capture overall cusp placement but not the sharp ridges between cusps. **Bump u to 8-16 and r to 0.1 for tooth data** (a 1-line config change, doubles the detail density).

5. **The KITTI 4× consistency improvement is the strongest empirical H5 evidence in the paper** — the model didn't just transfer, it *denoised* the raw partial scans. This is a generalizable principle: **a strong shape prior applied to noisy data is a denoiser, not just a hallucinator.** For our project, this means: even when our patient IOS scans are partial, noisy, or have artifacts (gum tissue overlap, prep-margin shadows), the v0 model's H3-conditioned shape prior will denoise the prep boundary automatically. The "free points" trick from PVD (paper 012) is the architecturally-faithful way to capture this in the diffusion era.

6. **The t-SNE of global features (Fig 17)** shows clear category clustering with no labels. The 1024-dim global feature has learned a *semantic embedding* of tooth/cabinet/airplane/etc., even though we never told it which category each training example belonged to. **For our project, this means the v0 PCN will naturally learn "this is a molar" vs "this is an incisor" from the 8-tooth-class dataset, even with no FDI labels at training time.** A free byproduct of the FC bottleneck.

7. **The 2-PN-layer sweet spot (Fig 13)** — 1 layer is much worse, 3+ layers give no gain. This is the right *budget* for our project: 2 PN layers is enough. Don't waste engineering on deeper encoders when the marginal gain is zero.

Promote PCN to v0 baseline (CRITICAL CONCRETE ACTION).** Add a 4th pilot to the existing 3-way PoinTr/SnowflakeNet/SeedFormer/AnchorFormer completion backbone comparison (papers 008–011): **PCN trained from scratch on the 3DTeethSeg22 + synthetic-10k-arch dataset, evaluated on the same 100-tooth subset as the other 3 backbones.** Compute cost: ~$30 on Lambda for training (6h on a single A100, by far the cheapest in our reading list), plus 1 day engineering to port the architecture to PyTorch 2.x + MPS for the M4 Mac mini demo. **PCN's 0.0012s/shape inference is the fastest in our reading list — the v0 should also include a "PCN-only" inference-only path for the real-time chairside preview demo** (skip the SDF lifting + FlexiCubes extraction, just show the 16k-point cloud as a low-fidelity preview while the full v0 runs in the background).

**2. Adopt stacked-PN encoder verbatim (CRITICAL DESIGN CONSTRAINT).** Do **NOT** use PointNet++ set-abstraction as the encoder for partial arch point clouds. The PCN paper's PN2 ablation (Fig 3) shows PointNet++ loses to stacked-PN on this exact task because of unstable kNN neighborhoods on partial data. **Stacked 2-layer PointNet → 1024-dim global feature is the right encoder budget** (Fig 13 ablation). For our v0 PVD-AF-DiGS-FC stack, the "AF" (AnchorFormer) component already uses a different encoder (DGCNN + transformer), so this constraint is satisfied for v0 — but if we add a v0-baseline PCN pilot, it should use the exact stacked-PN architecture.

**3. Bump folding grid for tooth data (small change, large impact).** Change u=4 → u=8 and r=0.05 → r=0.1 in the folding decoder (4× more points per coarse patch, 4× larger local window). The paper's hyperparameters are tuned for ShapeNet objects in a unit bounding box; tooth cusps need finer local detail. **Cusps are the visible feature of a crown — the v0 cannot under-detail them.** This is a 1-line config change with 4× more folding MLP invocations per shape (compute impact ~3-4× more, but the MLP is 3 layers of 512-512-3 = 790K params, so the memory is fine).

**4. Use CD as primary metric, EMD as secondary (metric decision).** Lock in CD for v0 evaluation. The paper's Fig 5 makes the case clearly: **CD concentrates error at missing regions (clinical fit is *exactly* this failure mode), EMD concentrates error at density mismatches (we care less about this).** Use EMD only as a *qualitative* sanity check that we're not over-concentrating points. This is consistent with PoinTr, SnowflakeNet, SeedFormer, AnchorFormer, PMP-Net++ all using CD as primary.

**5. Don't use the official PCN repo as a starting point (engineering caveat).** TF 1.12 + CUDA 9.0 + Python 3.5 + custom CUDA ops in `pc_distance/` = 1-2 days of dependency hell. **Port the architecture to PyTorch 2.x from scratch** — it's ~200 lines of model code: a 2-layer stacked PN encoder, a 3-FC-layer coarse head, and a 3-MLP-layer folding head. The CD/EMD losses are 20 lines of PyTorch (or use `pytorch3d.loss.chamfer_distance`). **Or use the LION repo (paper 005, NVIDIA Toronto) as a starting point** — it has a much more modern codebase that includes a PVD-compatible PVCNN module and a clean PyTorch 2.x test suite.

**6. v0 stack unchanged; PCN is a 4th pilot addition, not a replacement.** v0 stack stays **PVD-AF-DiGS-FC** at ~$2,200 Lambda (PoinTr free-points + AnchorFormer encoder + DiGS SDF lifting + FlexiCubes mesh extraction). **PCN is added as a 5th "cheap baseline" pilot** in the existing 3-way completion comparison (papers 008/009/010) → 4-way (008/009/010/**022**), plus the AnchorFormer winner (paper 011) → 5-way. Total v0 pilot budget: ~$2,300 (was ~$2,200, +$30 for the PCN baseline). **The 5-way completion pilot is now the v0 default** — it gives us a Pareto curve of accuracy vs. compute vs. inference speed, and PCN is the lower-left corner of that curve (cheapest, fastest, lowest accuracy).
