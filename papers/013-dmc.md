## TL;DR

**DMC is the closest published precedent to our v0 stack.** It frames dental crown design as a **point-cloud completion** task: given a partial arch (with the prepared-tooth region removed), generate the missing crown as a dense point cloud with normals, then convert to a printable mesh via a differentiable point-to-mesh layer. The architecture is a **transformer over per-region features**, very similar to PVD-AF-DiGS-FC but with a transformer core instead of DDM. Reaches **0.062 Chamfer** on a private dataset of prepped abutments + adjacent + opposing teeth.

## Why this matters for us

This is the paper that **most directly validates our v0 approach**:

1. **Same problem framing** — point-cloud completion conditioned on dental context.
2. **Same conditioning signal** — adjacent + opposing teeth (DMC: 2 + 3 = 5; we use full arch).
3. **Same output** — point cloud + mesh.
4. **Same metric** — Chamfer distance (we should aim to match or beat 0.062).
5. **Better data** — DMC uses **real prepped abutments** (which we don't have; we synthesize from complete arches).

**Strategic implications for our v0:**
- 0.062 Chamfer is the **first real benchmark number** for this task. Our 1-NN baseline (0.060) is already in the same range.
- The differentiator is data quality: with our complete-arch data (no real prep), the realistic v0 goal is **<0.060 Chamfer** in the simplest setup. Beating DMC's 0.062 is **plausible on real metrics** but the metric isn't directly comparable (different test sets).
- The architecture choices are similar enough that we can borrow DMC's "differentiable point-to-mesh" trick as a **drop-in replacement** for our planned FlexiCubes (or a complement to it).

## Method (from abstract)

1. **Feature extractor** — converts input point cloud into per-region feature vectors (local representation)
2. **Transformer** — predicts new feature vectors for the missing region (crown)
3. **Point reconstruction head + MLP** — predicts dense points with normals from the new features
4. **Differentiable point-to-mesh layer** — reconstructs the crown surface mesh from the dense points

This is **4 stages**, similar to our PVD-AF-DiGS-FC stack:
- Feature extractor: PointNet (DMC) vs PointNet++ (PVD/AF)
- Generation core: Transformer (DMC) vs DDM+attention (PVD+AF) vs SIREN+divergence (DiGS)
- Point output: MLP head (DMC) vs DDM denoising (PVD)
- Mesh extraction: Differentiable point-to-mesh (DMC) vs FlexiCubes (us)

**DMC's "differentiable point-to-mesh" is interesting** — we should read the full paper to see if it complements or replaces FlexiCubes for v1.

## Conditioning setup (DMC)

- **Context:** tooth **prepared** to receive a crown + 2 adjacent teeth + 3 opposing teeth
- **Total input:** ~5 teeth in point cloud form
- **Output:** the missing crown as dense point cloud + mesh

Compare to our v0:
- **Context:** full arch (12-14 teeth) with one tooth removed
- **Total input:** full arch (we have more context than DMC)
- **Output:** the missing tooth as 4096-point cloud + (planned) FlexiCubes mesh

We have **more context** (full arch) and **similar task framing**. If our model can't beat DMC's 0.062, it's an architecture problem, not a data problem.

## Connections to our hypotheses

- **H1 (2-stage > end-to-end):** DMC is 4-stage (feature → transformer → point → mesh), supports the staged approach.
- **H2 (latent diffusion > direct):** DMC doesn't use diffusion; uses a transformer for direct prediction. The H2 advantage is unclear from this paper.
- **H3 (conditioning on adjacent+opposing):** **DIRECT SUPPORT** — DMC's entire approach is built on this exact inductive bias. Same as our PVD free-points.
- **H4 (implicit SDF > explicit mesh):** DMC generates points + mesh directly, no SDF. So the H4 win is unclear here — but our v0 stacks DiGS for SDF, so we can compare.
- **H5 (synthetic pretrain → real fine-tune):** Not relevant — DMC is trained on real prepped data directly.

## For our project

1. **Borrow "differentiable point-to-mesh" trick** as a FlexiCubes alternative for v1. Read the DMC paper PDF for the layer design.
2. **Use 0.062 Chamfer as a soft target** for v0. Our baseline 1-NN is already 0.060; simple trainable should beat it; full v0 stack should aim for 0.040-0.050 range.
3. **Add a DMC head to our simple model** as a Phase 1.5 — replace the simple MLP decoder with a "differentiable point-to-mesh" head borrowed from DMC's repo. License-check first.
4. **Compare prep vs synthesized missing-tooth** — once we can run DMC's published architecture on our data, the gap in Chamfer will tell us how much the prep-data advantage matters.

## Caveats

- **Different test set** — DMC's 0.062 is on their own private dataset. Direct comparison with our 0.060 is apples-to-oranges.
- **Prep data** — we don't have it. Their number reflects the easier-to-fit prepped geometry. Our natural-tooth completion is harder in some ways (more variable anatomy) but easier in others (no prep line to fit precisely).
