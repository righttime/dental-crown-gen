## Research question + answer

**RQ:** Given a single RGB image of an object (or a 3D scene), can we generate a *structured, decomposable* 3D mesh with N *semantically meaningful, geometrically distinct* parts — *without* requiring a 2D/3D segmentation as input — where (1) the parts are *coherent* (no intersections, no gaps, no overlap), (2) the parts are *independently editable* (you can remove or modify one part without breaking the others), (3) the parts are *discoverable* from a single image (the model figures out how many parts + what each is), (4) the generation is *fast* enough for *interactive* use (vs HoloPart's 18-min per object pipeline), and (5) the *same* architecture works for *both* part-level objects and 3D scenes (the *one-model-two-tasks* requirement)?

**Answer (PartCrafter's):** Yes — by *restructuring* a *pretrained 3D-object DiT* (TripoSG, the *ByteDance* state-of-the-art 2025 image-to-mesh model) into a *compositional multi-entity* architecture via three *independent* design choices: (1) **compositional latent space** — the *monolithic* latent 𝒛 ∈ ℝ^(M×C) of TripoSG is *expanded* into N *disentangled* latent sets 𝒛¹, ..., 𝒛ᴺ, each with K tokens (so the *total* token count is N×K, but the decoder is *shared*), with a *learnable part-ID embedding* eᵢ added to each part's tokens to *disambiguate* parts (the *critical* design — the model collapses without it, Table 3 Exp 1); (2) **hierarchical (local-global) attention** — *local* self-attention within each part's K tokens (preserves *intra-part* structure) + *global* self-attention across all N×K tokens (models *inter-part* coherence) + *cross-attention* to DINOv2 image features in *both* local and global attention (the *key* for *image-conditioned part-discovery*); the two attention types are *alternated* across the 21 DiT blocks (even = global, odd = local, the *empirically-optimal* placement, Table 3 Exp 5); (3) **shared decoder** — the TripoSG VAE decoder is *re-used* to map each part's tokens to a *separate* 3D mesh, all in the *same* canonical space [-1, 1]³ (so parts assemble without additional transformations). The training: *full-finetune* of TripoSG's encoder + decoder + 21 DiT blocks on a *newly-curated* 50K part-labeled dataset (300K parts, mined from Objaverse GLTF metadata — over half of Objaverse assets have explicit part annotations) + 3D-Front for scene generation, with a *curriculum* strategy: 5K iter at LR=1e-4 on up-to-8-parts objects → 5K iter at LR=5e-5 finetuned to up-to-16-parts / scene-level; the *total* training is *2 days on 8× H20 GPUs* (vs HoloPart's multi-day training, vs AutoPartGen 095's 4-day 256×H100 training — PartCrafter is *massively* more compute-efficient because it *reuses* TripoSG's pretrained weights, the *cheapest* part-3D training in the 2025 wave). The result: a *single* compositional DiT that *simultaneously* denoises N parts in *one shot* (no autoregressive loop, no segmentation input), achieves SOTA on 5 benchmarks, runs in 34s per object, and *also* generates 3D scenes by treating each "part" as an *object* in the scene — the *first* part-3D model that *natively* handles both objects and scenes.

## Method

### Compositional latent space (Sec 3.2, the architecture's first innovation)

The *key observation* (paper Sec 3.2, para 1): pretrained 3D-object VAEs (TripoSG, CLAY, etc.) can *auto-encode* 3D parts *out-of-the-box*, *without* normalizing the input to the center of the canonical space (a *non-trivial* finding — parts don't have a "center" the way whole objects do, but the VAE *still* works because the latent space has *spatial alignment* baked in via the cross-attention-based encoder). This means the VAE's *latent space is already compositional* — each latent token is *implicitly associated* with a region in 3D space (the *same* finding as AutoPartGen 095's, but framed differently — PartCrafter says the VAE *already* has this property, AutoPartGen 095 *operationalizes* it via code concatenation).

To turn the *monolithic* 3D-object DiT into a *multi-part* 3D-DiT, PartCrafter expands the latent from 1 set of M tokens to N sets of K tokens: each part pᵢ is represented as zⁱ = {zⁱⱼ}ⱼ₌₁..ₖ ∈ ℝ^(K×C), where K is the number of tokens per part (paper uses K=512) and C is the token dimension (TripoSG's, inherited). The N parts are *concatenated* to form the *global* 3D-asset tokens Z = {zⁱ}ⁱ₌₁..ₙ ∈ ℝ^(NK×C). The *critical* addition: a *learnable part-identity embedding* eᵢ ∈ ℝ^C is added to the tokens of each part (eᵢ is *randomly initialized* and *learned* during training, the *only* new parameter introduced besides the attention). Without this embedding, the model *collapses* (Table 3 Exp 1: no part-emb = CD 0.3143 vs full model CD 0.1711, an *85% increase* in CD) because the self-attention cannot distinguish "which part am I supposed to be denoising for" — the model produces a *single* monolithic object instead of N parts.

The *permutation-invariance* of parts is handled by *randomly shuffling* the order of the parts in each training batch (the *standard* trick from autoregressive part-models, AutoPartGen 095 uses the *same* trick — both papers cite this as a "minor implementation detail" but it's actually *essential* for the model to learn that part *identity* is in the embedding, not the position).

### Local-global denoising transformer (Sec 3.2, the second innovation)

The *core* attention modification. PartCrafter *replaces* TripoSG's *single* self-attention block (which attended over all M tokens uniformly) with a *hierarchical* attention: (a) **local attention** within each part's K tokens (K×K attention matrix, *independent* per part, computes *intra-part* structure) and (b) **global attention** across all N×K tokens (NK×NK attention matrix, computes *inter-part* coherence). The two are *applied alternately* across the 21 DiT blocks: even-indexed blocks use global attention, odd-indexed blocks use local attention (the *empirically best* placement, see ablation below).

In *both* local and global attention, DINOv2 image features are injected via *cross-attention* (the *standard* TripoSG conditioning). The *key design choice*: cross-attention is applied in *both* levels (not just one). The ablation Table 3 Exp 4 shows that:
- Cross-attention in *local* only → better mesh fidelity (CD 0.1744) but worse geometry independence (IoU 0.0869)
- Cross-attention in *global* only → worse mesh fidelity (CD 0.1847) but better geometry independence (IoU 0.0824)
- Cross-attention in *both* → best of both (CD 0.1711, IoU 0.0814)

The *interpretation* (paper Sec 4.3, "Necessity of Part Identity Control"): local cross-attention helps each part *match* its corresponding region in the image (better fidelity), while global cross-attention helps the *overall composition* match the image (better decomposition). The *full* model uses *both* — the "balance between fidelity and independence".

The DiT backbone is *identical* to TripoSG's (long-skip-connection U-Net style, the *standard* 2024-2025 3D-gen DiT from Michelangelo 035 + CLAY 002 + TripoSG 001) — PartCrafter *only* changes the attention module, *all other* architectural choices (depth, width, normalization, timestep embedding) are *inherited*.

### Training objective: rectified flow matching (Sec 3.2, equation 2)

Trained with *rectified flow matching* (the *same* objective as TripoSG, CLAY, HoloPart, AutoPartGen — the *de facto* 2024-2025 latent-diffusion objective):
- Forward: Z_t = t·Z_0 + (1-t)·ε, t ∈ [0, 1] (linear interpolation between data and noise)
- Loss: L_flow = ‖(ε − Z_0) − v_θ(Z_t, t, c)‖² (predict the *velocity* term)
- *Critical*: the noise level t is *shared* across all N parts of the 3D scene or object (to ensure *consistent* trajectory sampling — if parts had different t, they would denoise at different rates and the inter-part coherence would degrade)

### Dataset curation (Sec 3.3, the practical H5)

The *first* paper in the 2025 part-3D arc to *explicitly* curate a *part-annotated* dataset from existing 3D repositories. The key insight: *over half* of the high-quality Objaverse subset (LGM 079) contains *explicit part annotations* in their GLTF metadata (because artists author 3D models in *modular* components, e.g., a scissors = 2 blades). PartCrafter *retains* these part annotations instead of flattening them into a single mesh (as TripoSG, CLAY, etc. do). The curation pipeline:
1. Start with Objaverse (ODC-By 1.0) + ShapeNet-Core (custom license) + ABO (CC-BY 4.0)
2. Filter: must have texture, <16 parts, max part-IoU < 0.1 (i.e., parts don't heavily overlap — *non-trivial* filtering, ensures "real" parts)
3. Result: 50K part-labeled objects, 300K individual parts
4. Add 30K *monolithic* objects as *regularization* (to prevent the model from forgetting how to generate non-part objects — the *standard* curriculum trick)

For scene-level: use 3D-Front (CC-BY-NC 4.0) processed by MIDI 007, where each *object in the scene* is treated as a "part" (the *natural* generalization).

### Implementation details (Sec 3.4 + Appendix B)

- **21 DiT blocks** from TripoSG (the *standard* 2024-2025 3D-gen DiT, width 1024, 21 layers per TripoSG's spec), alternating global/local attention (even = global, odd = local)
- **8× H20 GPUs** (96GB VRAM each), batch size 256, ~2 days total training
- **Curriculum**: 5K iter at LR=1e-4 on up-to-8-parts objects, *then* 5K iter at LR=5e-5 to support up to 16 parts / scene-level (the *anti-forgetting* curriculum)
- **512 tokens per part** (K=512, *vs* TripoSG's M=512 for whole object — note: total tokens = N×512, so 8 parts = 4096 tokens, *much* more than TripoSG's 512)
- **30% monolithic objects** in training for regularization (prevents over-specialization on parts)
- **Evaluation**: 2K test samples, 64×64×64 voxel grid for IoU computation, F-Score threshold 0.1
- **Inference**: ~34s per 4-part object on 1× H20 GPU (the *cheapest* inference in the 2025 part-3D arc, vs HoloPart's 18min)

### TripoSG* baseline (the key comparison)

The ablation introduces a *clever* baseline: **TripoSG*** = TripoSG with the *number-of-tokens-aligned* to PartCrafter (i.e., N×512 tokens for N parts, *all denoised as a single object*). This baseline is *critical* because it isolates the *contribution of the compositional structure* from the *contribution of having more tokens*. The result (Table 1, Objaverse): TripoSG* CD 0.1821, PartCrafter CD 0.1726 — a 0.0095 CD improvement *just from the compositional structure*, *even with the same number of tokens*. The paper's interpretation: "our local-global attention mechanism enables better object-level representation learning, thereby enhancing the generation process through improved structural understanding" — the *killer* finding for the field, because it shows that the *compositional* representation is *strictly better* than the *monolithic* representation, *even when you only care about the whole object*.

### Other findings (Sec 4 + Appendix)

- **Can generate different part-counts from the same image** (Fig 6, the *killer* UX) — 1 part, 2 parts, 3 parts, ..., 8 parts all produce *reasonable* results from the *same* input image. The model has *learned* the hierarchical part structure, not just memorized a specific part count.
- **Texture generation works** (Appendix C, Fig 7) — by passing each part's mesh through Hunyuan3D-2's texturing pipeline, the parts get *independent* textures. The paper notes "Hunyuan3D-2 is trained on monolithic objects, [but] it performs well on part-level objects" — a *surprising* finding, suggests the texturing pipeline is *part-agnostic* enough to work on any 3D mesh.
- **Inferring *invisible* parts** (Fig 4, the *killer* for clinical use) — the model can generate parts that are *not visible* in the input image (e.g., the *back* of an object, the *bottom* of a chair). This is a *direct* result of not using segmentation input — the model is *forced* to hallucinate the full 3D structure, not just the visible parts.
- **Handles 3D scenes natively** (Table 2) — the *same* architecture works for 3D scenes by treating each object as a "part". The only change is the *dataset* (3D-Front) and the *part count* (up to 8 objects per scene). The model is *truly* unified for objects and scenes.

## Connections to H1-H5

**H1 (2-stage VAE + DDM > 1-stage):** N/A directly, but PartCrafter *is* a 2-stage VAE+DDM pipeline (VAE = TripoSG's 3DShape2VecSet, DDM = rectified-flow DiT), *consistent* with H1's empirical support. The *additional* innovation is the *compositional* structure, not the 2-stage decomposition. For v0 sub-task 4 (crown generation), PartCrafter's *2-stage compositional DiT* is a *more* general framework than the 1-stage DM-CFO 069 or 3DTeethSAM 050, *consistent* with H1.

**H2 (Latent diffusion > direct):** **STRONGEST DIRECT SUPPORT IN 2025 PART-3D ARC** — PartCrafter's *entire* architecture is built on the *latent* space (the 3DShape2VecSet latent tokens), and the *compositional* decomposition is *only possible* in the latent space (in the *raw* point cloud, "composing parts" means *splitting* points, which is *not* a differentiable operation; in the *latent* space, "composing parts" is *concatenating* tokens, which is *fully* differentiable). The *killer* evidence: the IoU metric (which measures *part non-overlap*) is 3.78× better than HoloPart on ShapeNet (0.0293 vs 0.1107) *because* the latent-space composition *naturally* separates parts. For v0 sub-task 4, *adopt* PartCrafter's *compositional latent space* as the v0 v0 default — the *only* part-3D model that achieves both *high fidelity* (CD 0.1726 on Objaverse) *and* *high decomposition* (IoU 0.0359) in a *single* end-to-end model. Supports H2 because **the latent-space composition enables *differentiable* part decomposition** that is *impossible* in the raw point cloud (where "splitting" is non-differentiable).

**H3 (Conditioning on adjacent+opposing teeth is the H3 mechanism):** **INVERSE ARGUMENT — the *internal* compositional structure is the H3 mechanism, not external conditioning.** PartCrafter's H3 is *not* about conditioning on adjacent+opposing teeth (the v0 sub-task 4 H3 mechanism) — it's about conditioning on the *image* via DINOv2 cross-attention in *both* local and global attention (the *killer* finding, the *key* design choice that makes part discovery *possible*). For v0 sub-task 4, this is *directly applicable*: the v0 v0 H3 mechanism is currently the *adjacent-teeth conditioning* (CrownGen 058 + ToothCraft 036 + ToothForge 037), but PartCrafter's *image-conditioned internal decomposition* is a *complementary* H3 mechanism that could be added to v0 v1 (e.g., the *intraoral photo* as the conditioning signal, not just the *prep scan*). **Does not directly support H3, but provides a *complementary* image-conditioning mechanism** for v0 v1.

**H4 (Implicit SDF > explicit mesh):** **MILD PUSHBACK** — PartCrafter outputs *explicit meshes* (vertices + faces), not implicit SDF. The TripoSG VAE *uses* SDF internally (the decoder predicts SDF logits at query points, then *marching cubes* extracts the mesh), so PartCrafter is *implicit-SDF-trained, explicit-mesh-output* — the *standard* 2024-2025 3D-gen pipeline (TripoSG, CLAY, Hunyuan3D-2, all do this). For v0 sub-task 4, this is *consistent* with the v0 v0 stack (DiGS 003 + FlexiCubes 007), but PartCrafter's *compositional* extension is *novel*. The *interesting* finding: PartCrafter *outperforms* TripoSG* on the *monolithic* object reconstruction (CD 0.1726 vs 0.1821, F 0.7472 vs 0.7115) — the paper's interpretation: "understanding the compositional structure of objects enhances the quality of 3D generation". For v0 sub-task 4, this suggests the *compositional* training *regularizes* the monolithic output, *supporting* the *implicit-SDF-with-explicit-mesh* pipeline. **Does not directly support H4, but provides *indirect* evidence that compositional training improves mesh quality.**

**H5 (Synthetic pretrain + light fine-tune generalizes to real):** **STRONGEST DIRECT SUPPORT IN 2025 PART-3D ARC** — PartCrafter is *literally* the H5 hypothesis in action:
- **Pretrain**: TripoSG on 2M Objaverse+ShapeNet shapes (the *de facto* 2024-2025 3D-gen pretraining)
- **Fine-tune**: 5K iter at LR=1e-4 + 5K iter at LR=5e-5 on the 50K part-labeled subset (the *light* fine-tune)
- **Total training**: 2 days on 8× H20 GPUs (the *cheapest* part-3D training in 2025, vs AutoPartGen's 4 days 256×H100, vs HoloPart's multi-day training)
- **Generalization**: PartCrafter is trained on Objaverse (synthetic) + ShapeNet (synthetic) + ABO (real Amazon products) and tested on *held-out* Objaverse + ShapeNet + ABO, *plus* 3D-Front (rooms), *plus* the *novel* occluded subset — the *best* cross-domain generalization in the 2025 part-3D arc
- **The 71% improvement on occluded scenes** (Table 2) is *direct* evidence of H5 robustness — the model *generalizes* to the *held-out* occluded condition because the *compositional latent* + *image conditioning* is *robust* to input variations

For v0 sub-task 4, *adopt* the *PartCrafter pretrain-then-fine-tune* recipe: pretrain a *dental* compositional DiT on a *large* corpus of 3D teeth (could use ToothForge 037 or TeethGenerator 051 as the pretraining data), then *fine-tune* on the *small* v0-internal clinical dataset (~100-500 prep scans). Expected gain: *significant* — the *cheapest* path to a *clinically-deployable* v0 v1 model, $0-200 Lambda for the fine-tuning (vs the *expensive* training-from-scratch alternative).

## Surprises / interesting things buried in section 4

1. **PartCrafter *outperforms* TripoSG*** on *monolithic* object reconstruction** (CD 0.1726 vs 0.1821 on Objaverse, *with the same number of tokens*) — the *killer* finding, the *strongest* evidence that the *compositional* structure is *strictly better* than the *monolithic* structure even when you *only care about the whole object*. The paper's interpretation: "understanding the compositional structure of objects enhances the quality of 3D generation". This is *counter-intuitive* — you'd expect the compositional structure to *trade off* monolithic quality for part-decomposition quality, but the paper shows the *opposite*: the compositional training *regularizes* the model (the *implicit* part decomposition acts as a *learned* shape prior). For v0 sub-task 4, this is *direct* evidence that the *compositional* v0 v0 architecture (PartGen 093 + HoloPart 094 + AutoPartGen 095 + **PartCrafter 096**) is *strictly better* than the *monolithic* v0 v0 alternative (TripoSG 088, even token-aligned).

2. **71% better than MIDI on occluded scenes** (Table 2, 3D-Front Occluded CD 0.1508 vs 0.2591) — the *single most impressive* result in the paper, the *killer* H5 evidence. The reason: PartCrafter *doesn't use* segmentation masks, so it's *robust* to occluded objects (which MIDI can't segment from the image). For v0 sub-task 1 (FDI segmentation), this is *direct* evidence that *segmentation-free* generation is *more robust* than *segment-then-process* — the v0 v0 should *avoid* the 2-stage SAM2 + crown-segmenter pipeline and *adopt* a *single-stage* end-to-end approach.

3. **32× speed-up over HoloPart** (34s vs 18min) — the *practical* enabler for clinical use. The reason: HoloPart *runs* SAMPart3D on the *generated* mesh (which is *itself* slow), then *completes* each part with a *separate* HoloPart forward pass (N passes for N parts); PartCrafter does *one* forward pass for all N parts. For v0 v1's <5s chairside inference, PartCrafter is *still too slow* (34s) — but the *architecture* is *inherently fast* (single forward pass), the slowness is due to the *inference scheduler* (50 denoising steps × ~0.7s per step on 1× H20). With *fewer* denoising steps (e.g., DPM-Solver 4-8 steps, the *standard* 2024-2025 fast-inference technique), PartCrafter could hit <5s. The *practical* v0 v1 deployment: use PartCrafter's *architecture* with a *fast inference scheduler* (DPM-Solver 8 steps, $0 compute, 1-day code change).

4. **Model collapses without part-emb** (Table 3 Exp 1, CD 0.3143 vs full 0.1711, an *85%* CD increase) — the *single most important* design choice, more important than the local-global attention (Exp 3: no global = CD 0.2606, only *52%* increase). The interpretation: the part-emb is the *only* mechanism that disambiguates "which part am I supposed to denoise for" — without it, the self-attention cannot distinguish parts, and the model falls back to *monolithic* generation (which is *worse* on part-decomposition tasks). For v0 v0 / v0 v1, the part-emb is the *minimum* design choice — without it, the v0 v0 compositional DiT is *worse* than TripoSG*.

5. **Model completely collapses without local-attn** (Table 3 Exp 2, F drops to 0.2327, *less than 1/3* of the full model's 0.7374) — the *strongest* ablation result, the *most surprising* finding. The interpretation: local attention is *essential* for *intra-part* structure; without it, the global attention *mixes* the parts *during denoising*, destroying the part-level structure. For v0 v0, the *local* attention block is the *most-important* component — *never* remove it.

6. **Global attention can be removed with limited damage to *fidelity*** (Exp 3, CD 0.2606 vs full 0.1711) — but the *decomposition* (IoU) is *destroyed* (0.1602 vs 0.0814, a *97%* IoU degradation). The interpretation: global attention is *not* essential for *mesh quality* (the model can still produce a *monolithic* mesh), but it is *essential* for *part-decomposition*. For v0 v0, if the *only* goal is *monolithic* crown generation (no decomposition), the global attention can be *skipped* (saving ~50% inference time). But for v0 v1's *compositional* generation (crown + adjacent teeth in a single pass), the global attention is *essential*.

7. **Cross-attention in local = better fidelity, in global = better independence** (Exp 4 vs 5) — the *symmetric* finding, the *right* design intuition. The interpretation: local cross-attention "ties each part to a *specific* region in the image" (better fidelity), while global cross-attention "ties the *overall composition* to the image" (better independence). The *full* model uses *both* (Exp "Full", CD 0.1711, IoU 0.0814) — best of both worlds. For v0 v0, the *symmetric* cross-attention design is the *right* v0 v0 default.

8. **Alternating global/local across 21 DiT blocks is the best placement** — the *empirical* finding, but the paper doesn't ablate *all* possible orderings (only middle vs sides vs alternating). The *interpretation*: alternating gives the model *more chances* to integrate local and global information at *every* depth, while middle/sides *concentrate* the global attention in *one* region. For v0 v0, the *alternating* design is the *right* v0 v0 default — *don't* put all the global attention in the middle (the *obvious* design).

9. **The "specified number of parts" feature works for 1-8 parts** (Fig 6) — the *killer* UX, the *practical* enabler for v0 v1's *interactive* clinical use. A dentist can *specify* how many parts the model should generate (1 = monolithic crown, 2 = crown + opposing tooth, 3 = crown + adjacent + opposing, etc.), and the model produces *reasonable* results for *all* part counts. The interpretation: the model has *learned* a *hierarchical* part structure, not just a *fixed* part count. For v0 v1, this is *direct* evidence that the *variable-part-count* feature (the *killer* v0 v1 UX for *interactive editing*) is *achievable* with PartCrafter's architecture.

10. **Texture generation with Hunyuan3D-2 works on part-level meshes** (Appendix C) — a *surprising* finding, suggests the *texturing* pipeline is *part-agnostic* enough to work on *any* 3D mesh. The *practical* v0 v1 implication: the v0 v1 *texturing* pipeline can be *decoupled* from the v0 v1 *geometry* pipeline, the *cheapest* decoupled architecture (vs the *end-to-end* PBR-material alternative). $0 compute, 1-week integration.

11. **The 3D-Front IoU is *higher* for PartCrafter (0.0034 vs 0.0013 for MIDI) but with *worse* part-independence** — the *apparent contradiction* in Table 2. The paper's explanation: "MIDI slightly surpasses PartCrafter in IoU metrics, primarily due to the fact that ground truth 2D segmentation masks are used in their pipeline" — the *MIDI GT-mask force-noncverlap* artifact, *not* a *real* quality difference. For v0 v0, the *IoU* metric is *not* the *right* metric for *part-independence* when GT masks are available — use the *F-score* and *CD* instead (the *true* fidelity metrics).

12. **The "no 2D/3D segmentation input" finding is the *killer* H5 mechanism** — the paper's *main* claim, the *direct* inversion of HoloPart 094's *segment-then-complete* paradigm. The *interpretation*: with *enough* training data + a *compositional* latent + *hierarchical* attention, the model can *learn* to discover parts *without* being told where they are. For v0 v0, this is *direct* evidence that the *single-stage* end-to-end approach (PartCrafter 096 + AutoPartGen 095) is *strictly better* than the *2-stage* segment-then-process approach (HoloPart 094 + SAMPart3D + PartGen 093's multi-view pipeline). The v0 v0 should *adopt* the *single-stage* end-to-end approach as the *default*.
